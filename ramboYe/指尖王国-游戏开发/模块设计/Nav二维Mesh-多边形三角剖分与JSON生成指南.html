Nav 二维 Mesh：从多边形到寻路 JSON

在 X–Z 二维世界坐标中画出可行走区域，把区域三角剖分，再导出可被 cmlib/nav 读取的 Vertices + Triangles。页面末尾附带一个可实际操作的单多边形编辑器。

核心概念坐标系创建轮廓障碍与洞三角剖分JSON在线编辑器生产方案验收清单

先建立正确心智模型

你交给 nav 的不是“障碍物列表”，而是已经剖分好的可通行面积。每个三角形都是可以站立和移动的区域；没有被三角形覆盖的地方，就是不可通行区域。

Vertices：全局点表每个点只有整数 X、Z。三角形不复制坐标，只引用点表下标。
Triangles：可走三角形每项三个整数，例如 [0,1,4]，表示用顶点 0、1、4 构成一个可走三角形。
公共边：通行门户两个三角形使用完全相同的两个顶点下标时，公共边才会被识别为可穿越门户。
关键：只让两条边在几何位置上重合还不够。它们必须引用同一对顶点 ID，否则会产生 T-junction 或裂缝，寻路图不会连通。

1. 二维坐标系：用 X 和 Z，不用屏幕 Y

geo.Coord 只有两个 int32 字段：

type Coord struct {
    X int32
    Z int32
}
  • X 轴：向右增加。
  • Z 轴：建议在编辑器中画成向上增加。
  • 屏幕坐标换算：浏览器像素 Y 向下，所以显示时使用 screenY = bottom - Z * scale。
  • 整数单位：项目注释中 60000 对应 60 米，因此现有数据可理解为 1000 单位约 1 米。
数据始终保存世界 X/Z；屏幕翻转只属于编辑器显示层。
推荐地图范围：0 ≤ X < width、0 ≤ Z < height。现有 SearchGrid 也按照非负坐标定位。

2. 你应该怎样创建一个可通行多边形

1

先画外轮廓

沿着可通行区域边界连续点选顶点。建议统一使用逆时针顺序。最后一条边由最后一个点自动连回第一个点，不要重复写首点。

2

轮廓必须是简单多边形

边不能自相交；不能出现相邻重复点；尽量移除完全共线的中间点；至少需要 3 个点，面积不能为 0。

3

控制精度和吸附

编辑器应提供网格吸附，例如 1000 单位。相邻区域必须吸附到同一个顶点对象，不能各自生成“坐标相同、ID 不同”的点。

4

保留足够通道宽度

nav 会在门户边两端各取一个距端点 1000 单位的拐点（geo.TruncEdge）。因此共享边最好明显长于 2000 单位，实际还应叠加单位半径和安全边距。

3. 障碍物不是额外字段，而是“洞”

假设整个矩形地图可走，中间有一栋建筑不可走。编辑器中的原始几何应保存为：

  • 一个外轮廓：地图可行走边界。
  • 零到多个洞轮廓：建筑、水面、悬崖等障碍。
不要把整个外矩形先剖分，再额外输出障碍多边形。MeshCfg 没有障碍字段，障碍内部如果仍有三角形，寻路就会把它当成可走区域。

生产编辑器应使用支持洞和约束边的三角剖分算法。页面内置的教学编辑器只处理单个简单多边形、无洞；障碍洞的完整支持应放在正式编辑器导出器中。

4. 从轮廓到三角形

对一个有 n 个点、无洞的简单多边形，最终会生成 n-2 个三角形。教学编辑器采用耳切法：

  1. 把轮廓统一为逆时针。
  2. 找到一个凸顶点，取“前一点—当前点—后一点”作为候选耳朵。
  3. 若其他轮廓顶点都不在候选三角形内，就输出该三角形，并从轮廓中移除当前点。
  4. 重复，直到只剩最后一个三角形。
为什么三角形适合寻路：三角形一定是凸的，三角形内部任意两点可以直接连线；两个三角形共享边时，这条边自然成为通行门户。

一个 L 形示例

Vertices:
0=(100000,100000)  1=(500000,100000)  2=(500000,300000)
3=(300000,300000)  4=(300000,500000)  5=(100000,500000)

可能的 Triangles：
[0,1,3], [1,2,3], [5,0,3], [3,4,5]

注意：三角剖分结果不唯一，只要覆盖完整、互不重叠、没有越过边界即可。

5. 最终 JSON 必须长什么样

GenMeshCfg 读取的是 []*MeshCfg，所以文件最外层是数组。建议明确输出 ID：

[
  {
    "ID": 1,
    "Vertices": [
      {"X": 100000, "Z": 100000},
      {"X": 500000, "Z": 100000},
      {"X": 500000, "Z": 300000},
      {"X": 300000, "Z": 300000},
      {"X": 300000, "Z": 500000},
      {"X": 100000, "Z": 500000}
    ],
    "Triangles": [
      [0, 1, 3],
      [1, 2, 3],
      [5, 0, 3],
      [3, 4, 5]
    ]
  }
]
字段约束典型错误
IDint32；用于区分配置项单配置可省略，但建议编辑器始终输出
VerticesX/Z 都必须是 int32 整数输出小数、屏幕 Y、负坐标或越界坐标
Triangles每项恰好三个合法顶点下标下标越界、重复点、零面积、交叉覆盖
共享边相邻三角形引用同一对顶点 ID坐标相同但点 ID 不同，导致图断开

代码依据：cmlib/nav/navmesh.go:33-44 读取数组；navmesh.go:47-64 按三点下标创建三角形。

7. 正式编辑器建议的生成流水线

A

编辑层

保存地图边界、多个可走轮廓、障碍洞、区域标签、单位半径和安全边距。源文件可以是编辑器自己的 JSON。

B

几何清洗

坐标量化为 int32；按容差吸附/合并重复点；删除短边和共线点；检查自相交、洞是否位于外轮廓内、轮廓之间是否重叠。

C

按单位半径膨胀障碍

如果寻路坐标代表单位中心，障碍边界应向外扩张“单位半径 + 安全距离”，或者将可走边界向内收缩。否则点路径合法，实际模型仍可能擦墙。

D

约束三角剖分

输入外轮廓和洞，所有轮廓边都是不可跨越约束边。输出只覆盖可走面积的三角形。复杂地图优先选择成熟的约束剖分实现，而不是自行扩展教学耳切。

E

全局顶点去重与索引

为坐标建立唯一顶点表，三角形统一引用全局下标。共享边必须引用同一对下标。

F

验证、预览、导出

可视化三角形、边界边、公共门户和连通分量；验证通过后输出 []MeshCfg JSON，并在服务端实际加载、抽样寻路。

推荐保留两份文件

文件用途
map.navsource.json编辑器源数据：外轮廓、洞、区域语义、构建参数，可反复修改。
mesh.json运行时构建产物：只有 ID / Vertices / Triangles，直接交给 GenMeshCfg。

8. 导出前验收清单

  • 所有坐标均为 int32，且处于地图宽高范围内。
  • 轮廓没有自相交、重复相邻点和零长度边。
  • 每个三角形三个下标均合法且互不相同，面积不为 0。
  • 三角形完整覆盖可走区域，互不重叠，没有覆盖任何障碍洞。
  • 内部边恰好被两个三角形共享；边界边只被一个三角形使用；不存在超过两个三角形共享同一边。
  • 所有相邻三角形真正复用相同顶点 ID，不存在 T-junction。
  • 门户边宽度满足单位半径和 TruncEdge 的安全要求。
  • 按玩法预期检查连通分量：该连通的区域必须连通，该隔离的区域不能误连。
  • 用 GenMeshCfg → NewNaviMgr → Route 跑边界点、障碍附近、狭窄通道和跨区域抽样测试。
最终一句话：编辑器负责“画可走面并可靠三角剖分”，nav 负责“把共享三角形边变成图，再在图上寻路”。两者的契约就是这个 Mesh JSON。
