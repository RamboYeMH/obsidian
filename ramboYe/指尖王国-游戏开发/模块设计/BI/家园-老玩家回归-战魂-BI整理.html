一、家园

5 张表的写入函数都在 game/play/internal/mplayer/player_bi.go:2275-2333，表名常量在 game/bi/def/table.go（常量名前缀是 BILogMarchHomeLand*）。每张表除了下面的字段，都带公共字段。

1. home_land_building_add家园建筑进仓库

触发：通过资产发放获得家园建筑时（ctl_asset.go:1816），按配置ID写一条。

字段含义类型
cfgId建筑配置 IDint32
count增加数量int64
reason来源 reason_id（例如家园商店购买 home_land_shop_buy）string

2. home_land_building_del家园建筑出仓库

触发：只有家园商店回收建筑时写，每回收 1 个写 1 条（ctl_home_land_build.go:645）。摆放、收回、装饰拆解从仓库移除建筑都不写这张表。

字段含义类型
cfgId建筑配置 IDint32
count减少数量（目前固定为 1）int32
reason目前固定是 home_land_shop_recyclestring

3. home_land_sign_reward家园签到领奖

触发：玩家手动领取签到奖励（ctl_home_land_sign.go:92），或者签到期结束时把没领的奖励用邮件补发（:207）。每个档位写一条。

字段含义类型
day签到天数档位（即签到配置 ID）int32
reasonhomeland_sign_reward（手动领取）/ homeland_sign_mail_reward（邮件补发）string

4. home_land_dawn_reward晨曦回礼领奖

触发：领取晨曦回礼（ctl_home_land.go:475）。

字段含义类型
rewards奖励列表[]TypIDVal
reasonhome_land_dawn_rewardstring

5. home_land_groom_reward打理奖励

触发：打理好友家园时，打理者和被打理者各写一条（ctl_home_land.go:767、:828，以及离线异步路径 :919、:956）。由 role_id 表示这条记录属于谁。

字段含义类型
targetPid奖励接收者的玩家 IDint64
groomerPid发起打理的玩家 IDint64
rewards奖励列表[]TypIDVal
reasonhome_land_groom_helper（打理者）/ home_land_groom_target（被打理者）string

6. 借用表 reward_id装饰拆解

触发：拆解装饰物，返还建筑材料（ctl_home_land_decoration.go:61）。字段 reward_list 是 [{RewardID}] 数组，按返还数量展开，里面放的是建筑 cfgID。

二、老玩家回归

回归玩法没有独立的 BI 表。下面 3 个活动走通用活动表 actv：由 InitBILogCommon（game/actv/internal/activity/template/base/base.go:130）生成记录，发到 play 模块后由 BILogUserActv（mplayer/player_bi.go:208）写出，Fields 和 Args 平铺成同一层字段。

actv 表的活动公共字段

字段含义
scope活动范围：server / player / union
actvName活动名称（中文标题）
subOperation具体操作，用来区分是哪个活动（见下表）
startTs活动开始时间
actvID活动唯一 ID
cfgID活动配置 ID
ownerID活动所有者

各回归活动的专有字段

活动subOperation专有字段触发
回归活动 - 重启征程（登录）login_restartloginDays：累计登录天数活动期间每日首次登录（login_restart/logic.go:61）
回归活动 - 新的旅程newJourneyuser_id：原角色 ID
new_user_id：新角色 ID
new_server_id：新服务器 ID		玩家选择去新服（new_journey/ctl.go:68）
回归活动 - buffreturn_buffbuffIDs：发放的 buff ID 列表
duration：持续时长		play 模块确认 buff 发放成功后（return_buff/logic.go:54）

注：BI 字典原来把重启登录的 subOperation 写成 restart_login，和代码里的 login_restart 不一致，xlsx 里已按代码改正。

war_soul战魂升级流水

触发：每次战魂升级成功（ctl_war_soul.go:360）。related_id 就是本次的 operationID，和 623、624 两条资产流水共用同一个 ID，可以互相关联。

字段含义格式
hero_id被升级的 SSR 唯一 ID字符串
hero_cfg_id被升级的 SSR 配置 ID字符串
old_lvl / new_lvl升级前 / 后的战魂等级字符串
old_exp / new_exp升级前 / 后当前等级的经验字符串
add_exp本次投放折算出的战魂经验字符串
frag_detail消耗的碎片明细道具ID*数量,...，没有消耗时为 -
hero_detail消耗的英雄本体明细uid/cfgID/star星级/q品质,...，没有消耗时为 -
max_star本次消耗的英雄本体里最高的星级字符串，用来筛查高价值消耗
