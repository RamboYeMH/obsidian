三、原因与处理方案

问题点 1 · 根因
QueryMailMeta 空 map 与建号漏写
mail_storage_new.go:1057 无文档时返回非 nil 空 map；且 UserMailGroup（handler.go:1336）创角首次插入 mail_group 时完全未初始化 mail_meta.subscribe_group（A）。
问题点 2 · 绕过漏洞
入盟增量只写单键击穿 len==0
a8be7a7f2 仅改了 len(ownMails.SubscribeGroup) == 0，但新号入盟时 UserMailGroup（handler.go:1344-1359）只写 subscribe_group.2，使 len == 1 绕过守卫（A）。
问题点 3 · 兜底缺失
doLogin 按组拉取无零值拦截
handler.go:221 读取 ownMails.SubscribeGroup[group.GroupType] 时未判断 lastTimestamp <= 0，缺失的 GroupType=3 直接退化为 0 拉取全表（A）。

修复与处理方案（服务器/gs/mail/webserver/mailserver）

  • 修复 1（handler.go:221 doLogin 增加组级零值兜底，最关键止血点）：在遍历 relation.Groups 读取 lastTimestamp := ownMails.SubscribeGroup[group.GroupType] 时，若 lastTimestamp <= 0，立即调用 updateSubscribeGroupInfo(uidStr, cspb.MailAddrType(group.GroupType), util.NowTs()) 并 continue 跳过本次历史拉取，绝不允许将 lastTimestamp = 0 传入 QueryNewMailsAfterTimestamp。
  • 修复 2（handler.go:1336-1359 UserMailGroup 创角同步初始化 subscribe_group）：当 group == nil 首次创建玩家的 mail_group 时，同步遍历 res.Groups 为所有初始邮件组（如 MailAddrSyc=3）写入当前时间戳 util.NowTs()。
  • 修复 3（重新编译并发布独立 mailserver 进程）：mail/main.go 为独立部署的全局邮件 Web 服务，合入补丁后必须单独构建并重启/发布线上 mailserver 实例。
