小号收到老邮件——成因复核

依据：mail/webserver/mailserver 与 game/play/internal/ctl_mail.go 源码（分支 h5_new_tf_v1054）

结论：bug 确实存在，但原文档对"修复后为什么还有"的解释站不住，"正常创角 100% 复现"也说过头了。

入盟路径能绕过守卫，这一点成立。但今天的样例 13029098 没有联盟（guild_id=0），这条路径解释不了它。按当前代码，无联盟新号不会触发，所以更可能是线上 mailserver 没部署 a8be7a7f2。

说对了的部分

成立

10703971 的成因

这个号 07-15 创角，当时 H5-10969 还没修：

  • 新号还没有 mail_meta 记录时，QueryMailMeta 返回非 nil 的空 map（mail_storage_new.go:1057）；
  • 修复前的守卫是 SubscribeGroup == nil，空 map 拦不住；
  • handler.go:221 取到 lastTimestamp = 0，QueryNewMailsAfterTimestamp 把公共邮箱 h5_3_282 里所有未过期邮件都拷进了玩家邮箱。
成立

入盟只写 key 2，绕过 len==0

创角 → syncMailGroup → UserMailGroup（group == nil，handler.go:1344）
        └ 只写 mail_group，不写 subscribe_group
入盟 → unionMailSubscribe（ctl_union.go:2203）→ syncMailGroup → UserMailGroup
        └ 只对 GroupType=2 调 updateSubscribeGroupInfo（handler.go:1356）
        └ SubscribeGroup = {2: ts}，len == 1，通过守卫（handler.go:205）
首次 /login → doLogin
        └ SubscribeGroup[3] 为零值 0 → 全量拉取全服邮件

触发条件：新号在第一次打开邮件（/login）之前就加入了联盟。

成立

修复 1 方向正确

在 doLogin 里按组判断 lastTimestamp <= 0：补写当前时间戳后 continue，不拉历史邮件。这是最稳的兜底，不依赖调用顺序。

有问题的部分

矛盾

无联盟样例 13029098 解释不通

没入盟就走不了路径 B。修复后，普通新号第一次登录时 len == 0，会调用 initSubscribeGroupInfo 初始化 key 2 和 key 3（logic.go:250），不会拉老邮件。

我检查了所有写 mail_meta 的地方：doMailTransfer、batchUpdateMailMeta、updateNewMailTimestamp、UpdateMailMeta，都不会造成只有部分 key 的情况，代码里找不到其他触发路径。所以更可能是：

  • 线上 mailserver 没部署 a8be7a7f2；或者
  • 数数里的 guild_id 不是领邮件那一刻的值。
错误

把提交时间当成了上线时间

a8be7a7f2 是 07-22 提交到 h5_new_tf_v1048_mail 上的，之后进了 1049 系列分支。原文"07-23 起 = 修复后"的划分没有依据，那 3,186 人里有多少是修复没上线、有多少是真的绕过了守卫，目前分不清。

过度

"正常创角 100% 触发"

按当前代码，只有"先入盟、再首次打开邮件"才会触发，或者线上跑的是旧版本。复现步骤里"进主城后自动 /mail/polling"这一步，在新代码下恰好不会触发。

混淆

"路径 A（空 map / 独立进程未拦截）"

这条把修复前和修复后的情况混在了一起。空 map 正是 a8be7a7f2 已经修掉的问题，修复后不再是一条独立的绕过路径。

次要

修复 2 只覆盖 group == nil

这次修复的主力还是修复 1，修复 2 可有可无。
