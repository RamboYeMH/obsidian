王座上的「幽灵驻防」是怎么来的

幽灵部队 X 7692424334472598780（归墟 · 玩家 11329956） 旧防守集结 rt 7692382570210332360（车头 11195874 · 天赐凌渊） 王座 1001
结论（日志 + 代码核实）

防守集结 rt 的车头 11195874 主城在王座焦土范围内，被敌方打败后击飞。击飞流程 OnP2MCityKickOut 会解散他当车头的所有集结，其中就有正在和 X 交战的王座防守集结 rt。

解散时成员逐个退出，每退一支都会同步触发 kingWarAutoOccupy。最后一支退出后，X 自动占领王座。但 base.DefendID 还是 rt 的 ID，所以 X 被塞进了正在解散、还没从地图删除的 rt。塞入时的 DelUnit(X) 又嵌套触发 rt 的战斗结算和二次解散：X 先被放回地图，返回后又被删掉。

最后 X 不在地图上，也不在任何集结里，但 Defenders 和 DefenderEnterTime 里还留着它，成了「幽灵驻防」。

不需要 GM：线上就是正常玩法自然触发的。整个过程发生在同一帧、同一个调用栈里，耗时 13ms。

先回答：是不是同一帧？

是。从 .143 到 .156，全部是 game850 地图协程处理一条消息 P2MCityKickOutReq 时的同步调用，中间没有 tick，也没有让出执行。13ms 只是这段代码的执行耗时。

所以前面说的「每退一支，X 就再攻一次」，并不是又打了一场新战斗。它是在同一个调用栈里同步调用了 kingWarAutoOccupy → KingWarOccupyPTroop(X) → Arrive → pTroopArriveThroneAttack。日志里的 JoinBattlePassive SKIP … already has CurTarget 说明 X 本来就在打 rt，这次调用什么都没改变，只是又把 X 加回了 Attackers。

佐证：OnP2MCityKickOut 的日志 11195874 OnP2MCityKickOut …（ctl_city.go，线上 :748）打在函数末尾，出现在 .157，正好包住整段连锁。

缺陷点

位置问题
kingwar/logic.go Exit → model/base.go OccupyStopDefenders 清空、占领清掉时 不清 DefendID。新占领者用 GetDefendID() 拿到的是旧集结的 ID。根因
ctl_king_war.go pTroopArriveThroneOccupy「编队立即加入战斗」只检查 rt 在不在地图上，不检查它是否正在解散或结算，也不检查它是否还属于当前占领盟。根因
ctl_rallytroop.go AddDefenderIntoRallyTroopDelUnit(pt) 会同步触发对手集结的战斗结算和解散。解散时把 pt AddUnit 回地图，返回后又被删掉，部队凭空消失。放大器
ctl_rallytroop.go DisbandRallyTroop逐个召回成员时，rt 仍在地图上而且还在战斗中。每召回一支都会同步跑 kingWarAutoOccupy，让外部逻辑在「半解散」状态下操作 rt。触发条件

修复方向（未改代码）

  • Exit 里 Defenders 清空、执行 OccupyStop 时，把 DefendID 一并清零。这是最小改动，能直接切断「新占领者关联旧集结」。
  • pTroopArriveThroneOccupy 拉入集结前做校验：rt 的 DefendCtx 指向本王座、rt 不在战斗中、rt 车头和当前占领盟同盟；不满足就不拉。
  • 兜底：getOrCreateKingWarDefender 建集结失败时，把找不到的部队从 Defenders 和 DefenderEnterTime 一起清掉（现在 kingWarExit0 取不到 owner，只能删 Defenders）。

如何复现（不需要 GM）

线上就是自然触发的。关键是同时满足三个条件：

  1. 防守集结的车头主城在王座焦土范围内（CheckInThroneRange）。
  2. 这个集结正在和一支敌方部队交战。
  3. 这时车头主城被打败、被击飞。

车头怎么定：kingWarCreateRally 逆序遍历 Defenders，最后一个进驻的部队的主人就是车头（线上是 11195874，他的部队进驻得最晚）。

准备

  • 王座战处于战斗阶段。本服世界地图的王座战也可以，CheckThroneKickOut 不区分跨服。
  • 联盟 A（防守方）：玩家 L（车头），主城迁到王座焦土范围内，城防尽量弱；玩家 M，任意。
  • 联盟 B（进攻方）：玩家 X，派一支单部队攻打王座，兵力要够打几回合，不能秒死；玩家 B2，有能打赢 L 主城的部队或集结。

步骤

  1. 联盟 A 占领王座 1001：M 先派 1～2 支部队驻防，L 最后再派 1 支驻防，保证 L 的部队排在 Defenders 末尾。
  2. X 派单支部队攻打王座。预期日志：
    getOrCreateKingWarDefender: defender <DefendID> not found, creating rally troop pTroopArriveThroneAttack: unit X attacks defender <rt> L settarget >>>>>>>>joinpassive <rt> atk:X ← 前缀是 L，确认 L 是车头
  3. 在 X 和 rt 交战期间，B2 攻打 L 的主城并获胜。预期日志：
    L redif PCityDefendEnd troop city win:false （→ M2PCityKickOut → play → P2MCityKickOutReq 回到地图） UnionWatch_DelUnionAttackInfoWithBeOccupy … atkID:<rt> RemoveDefender … （rt 成员逐个退出，每条后面跟一条 pTroopArriveThroneAttack: unit X …） clearing throne 1001 occupation AddDefender … id:X … b.defenders:[] ThroneDefendEnd rt:<rt> InBattle :false kingWarRallyDisband TroopID:X … recall:false AddDefenderIntoRallyTroop pt:X, rt:<rt> L OnP2MCityKickOut …
    这时客户端上 X 从地图上消失（没有回城行军），但王座显示被联盟 B 占领。
  4. 验证残留：联盟 A 任一玩家再派部队攻打王座。预期日志：
    troop X not found when creating king war rally getOrCreateKingWarDefender: failed to create rally … marching arrived unit … handle failed
    复现成功。再接上 Bug/2026-10-03-王座占领任务卡在7分钟.html 里的步骤，就能复现占领时长零结算。

其他会走同一路径的触发方式

凡是在防守集结和敌方交战时，把它整个解散的路径都可能触发：

  • 车头主城被击飞：OnP2MCityKickOut，本案。
  • 车头跨服返回或转服：P2MCityKickOutReq{IsCross / IsChangeServer} 走的也是 OnP2MCityKickOut。
  • 车头被封号：OnP2MBandPlayer 同样会解散他发起的集结。

时间窗：步骤 3 必须落在 X 和 rt 交战期间。线上 X 20:56:16 开打，20:56:18 车头主城被破，相隔 2 秒。本地测试时，让 X 的兵力能撑几回合，B2 提前在 L 主城旁边埋伏，就比较容易对上时间。
