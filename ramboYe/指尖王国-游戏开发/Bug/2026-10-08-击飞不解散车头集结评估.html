主城被击飞时，不解散车头的集结会怎样

关联问题 王座幽灵驻防（Bug/2026-10-03-王座幽灵驻防成因.html） 分支 h5_new_tf_v1051_remote_fight_light Jira H5-12694（玩家驻防王座时未添加驻防事件） 实施分支 h5_new_tf_v1053_battle_defener 行号为本地分支
最终结论（2026-10-12）

建筑防守集结（王座、哨塔及其他建筑）：主城被击飞（不跨服）时完全不动；玩家离开地图（跨服、转服、遣返、强制迁城）时，只摘出他自己的部队，集结和战斗继续。主城防守集结、攻击集结保持原逻辑。

根因 DefendID 不清零已在 5 个建筑模型里修掉。实施细节见文末「最终方案：改动范围」和「影响范围」。下方原评估保留，过时的地方已标注更正。

速查：各类集结能不能保留

集结类型结论
主城防守集结必须解散，否则集结永久残留在地图上必须解散
等待中的攻击集结建议解散，集结点、花费返还、通知邮件都会乱建议解散
跨服返回或转服必须解散，玩家已离开地图，有空指针风险必须解散
王座或建筑防守集结可以保留，只撤车头部队可保留

每一类的详细原因见下方「问题三」。

现状：击飞时到底处理了什么

OnP2MCityKickOut（ctl_city.go:692）只做两件事：

  1. 解散主城防守集结：city.DelDefender() + DisbandRallyTroop(defender, Finish)
  2. 解散他当车头的所有集结：rt.Owner.ID == req.PlayerID → DisbandRallyTroop(rt, Cancel)

他的单支驻防、行军中的部队、加入别人集结的部队，在主城被击飞但玩家仍留在本图（IsCross=false）时本来就不动。之后召回时找不到主城，会走 recallPlayerTroop 的兜底（ctl_playertroop.go:627-637）直接瞬间回城。所以「主城没了、部队还在外面」这种状态，代码已经支持。

本案的 rt 是王座防守集结，车头是最后进驻的玩家（kingWarCreateRally 逆序遍历 Defenders），所以车头一被击飞，整个 rt 就被第 2 步解散，引出了幽灵驻防。

两种「不解散」的做法

A. 整个集结原样保留
  • 车头的部队也留在集结里
  • ↓
  • 车头已不在王座区域，却还在守王座，违背击飞的规则意图
  • rt.Owner、CityID 指向一个没有主城的玩家
  • 跨服返回时车头离开地图，集结成了无主集结
B. 只撤车头的部队，其他成员保留
  • 等同于车头手动召回自己的部队
  • ↓ 走现成路径
  • RecallTroop → giveUpDefend（退出王座、结算时长）+ giveUpRally → DelPTroopInRTroop
  • 本案剩 15 支，Defenders 不空，X 继续 ActAttack，不会触发幽灵驻防
  • 车头部队是最后几支时，照样触发

下面的分析以 B 为主。A 的问题是 B 的超集。

问题一：堵不住幽灵驻防

车头的部队被撤完后，如果 Defenders 正好空了，后面和线上一模一样：

车头最后一支部队退出 → kingWarExit → Defenders 清空 → OccupyStop DefendID 没清零，仍是 rt 的 ID → kingWarAutoOccupy → X 自动占领 → AddDefender(X) → pTroopArriveThroneOccupy：GetDefendID() 返回旧 rt ID rt 还在地图上：giveUpRallyOnDefend 只在守主城时删除空集结（ctl_rallytroop.go:731） → AddDefenderIntoRallyTroop(rt, X) → DelUnit(X) → BattleUnitDel → ThroneDefendEnd → kingWarRallyDisband：AddUnit(X)、DelUnit(rt) → DeleteUnitObj(X) X 消失，Defenders 里留下幽灵
更正（2026-10-12）：原推断"玩家交战中手动召回最后几支也会触发"不成立。checkRecallTroop（ctl_march.go:1104-1116）规定部队在防守集结里时不允许召回（ErrCodeRallyDefenseInBattle）。交战中能把部队摘出集结的只有系统路径：击飞、遣返、强制迁城。

问题二：集结里的「车头属性」不会跟着换

NewRallyTroop（mtroop/rally_troop.go:60）创建集结时，把这些属性从车头部队拷了一份，之后不会自动更新。目前也没有转移车头的接口。

属性来源车头撤走后影响
rt.Owner车头玩家仍是被击飞的玩家PushRallyNtf 推给他；KingWarOccupyRTroop 用 cache.GetPlayerCache(rt.Owner.ID) 取联盟（ctl_king_war.go:1783）；远征地图阵营判断也用它
rt.CityID车头主城指向已删除的主城更正：战报只在 rt.IsDefendCity()（守主城）时才按 CityID 找主城（packmail.go:54/233），建筑防守集结不受影响
BatCtx().PlayerID、CityLv车头更正：RemoveTroop 会把 PlayerID 设成新的 Troops[0]（rally_troop.go:410-413）战斗属性用 GetMaxPowerTroop()、战报展示用 GetMaxPowerMember()，都是实时取战力最高的编队，车头撤走后自动切换
Skin、BattleBehavior车头部队不变；王座集结在加人时会 CalPSH 刷新 BattleBehavior外观仍是原车头的
GetLeader()Troops[0]自动变成另一名成员的部队和 Owner 不再一致

主城被击飞（不跨服）时玩家还在这张地图上，这些不一致一般不会出错，主要是显示和归属不对。

问题四：玩法规则

  • 主城被击飞的本意是把这个玩家赶出王座区域。方案 A 让他的部队继续守王座，等于击飞失去了效果。
  • 方案 B 只撤他自己的部队，和「单支驻防不动、集结里只撤自己」的现状比较一致，但需要策划确认：被击飞的玩家，他的单支驻防部队要不要也撤？现在是不撤的。
  • 车头撤走后，集结的「发起人」显示要不要改成新的车头，也需要策划确认。

建议（原评估，已被「最终方案」取代）

优先级改动作用
必改kingwar.Exit 里 Defenders 清空、执行 OccupyStop 时把 DefendID 清零切断「新占领者关联旧集结」，覆盖击飞、封号、跨服、手动召回所有路径
必改pTroopArriveThroneOccupy 拉部队进集结前，检查 rt 的 DefendCtx 指向本王座，rt 不在战斗中，rt 车头和当前占领盟同盟兜底，防止部队被拉进半解散的集结
可选OnP2MCityKickOut：主城被击飞（不跨服）且 rt 是王座或建筑防守集结时，只撤车头自己的部队，不解散整个集结体验优化：一个人被击飞不会连累全盟驻防。其他类型和跨服场景保持现状
可选新增转移车头的函数：同步更新 Owner、CityID、BatCtx.PlayerID、CityLv，并通知客户端做可选项 3 时配套，解决问题二的归属不一致

只做可选项、不做必改项的话，本案能避开，但车头部队是最后几支、或者玩家手动召回最后几支时，仍会产生幽灵驻防。

问题五：交战中摘部队的链路（2026-10-12 补充）

每撤一支驻防，进攻方都会被"重新到达"

giveUpDefendOnKingWar（ctl_king_war.go:1538）在 kingWarExit 之后无条件调用 kingWarAutoOccupy：取出 base.Attackers（正在打 rt 的所有进攻部队）、清空，再逐个重走 ArriveCheck / Arrive。ArriveCheck 不通过的进攻部队会被 RecallTroop 强制遣返。冰髓矿、泰坦宝库、联盟战龙巢的放弃驻防也是"退出 + 自动占领"，同一个问题。

不能直接 DelUnit(rt)

DelUnit → BattleUnitDel 只对进攻方调 battleEnd，不会对 rt 调，所以不会走 ThroneDefendEnd。进攻方在 pTroopBattleEndAlive 里既没行军也没驻防，会被 RecallTroop 遣返（ctl_playertroop.go:1333-1342）：打赢了却回家，建筑没人占。

空集结要走正常战败

空集结的 TroopData.IsDead() 为真（battle/lineup.go:193）。battleTroopDead(rt)（ctl_battle.go:453）先对 rt 调 battleEnd → rTroopBattleEndDead → XxxDefendEnd(rt, false)：先删集结，再让进攻方自动占领；最后才对进攻方调 battleEnd，此时进攻方已在驻防，不会被遣返。

跨服遣返的现有 bug

ForceRecall 只处理援助主城，龙巢直接返回失败，其他建筑没有 case，返回 EntityNotFound。部队留在集结里，play 侧仍执行 ResetTroop，编队同时出现在两边。外服玩家的 MapPlayer 被 BaseOther.BackMapAndRun 删除后，战斗结束时 kingWarRallyDisband 执行 delete(mp.RallyTroopIDs, ...) 会空指针 panic。forceRecallAll（强制遣返、新手强制迁城）则会把整个集结连同进攻方一起清掉。

影响范围

场景改前改后
主城被击飞（不跨服），他是建筑防守集结的车头整个集结解散，交战中防守当场瓦解，进攻方不用打完就赢集结不动，他的部队继续驻守，和单支驻防一致；战斗输了时找不到主城，瞬间回城
跨服、转服击飞，他在建筑防守集结里只处理他当车头的；当成员的部队残留在集结里，王座上会空指针 panic只摘他自己的部队，集结和战斗继续
跨服王座战普通遣返建筑集结里的部队召回失败，编队两边各一份正常摘出并回城，兵力同步回 play
强制遣返、新手强制迁城他所在的建筑集结整个解散，进攻方也被强制清掉只摘他自己的部队
最后一个驻防退出，新部队占领新占领者可能被拉进残留旧集结后消失（幽灵驻防，即 H5-12694 的"未添加驻防事件"）DefendID 已清零，新占领者生成新 ID，不会进旧集结
交战中集结被摘空—按正常战败处理：先删集结，进攻方再按各建筑规则自动占领
什么是"交战中把防守集结摘空"：建筑的防守集结正在被敌人攻打，系统把集结里最后一支部队拿走，集结里一个人都不剩。
例：王座上 A、B、C 驻防，敌方 X 来打，系统把三人临时组成防守集结 rt 与 X 交战。打到一半 A、B 已离开集结，只剩 C；这时 C 跨服、转服、被遣返或强制迁城，系统用 defendRallyMemberLeave 把 C 摘出并瞬间回城，rt 变空但 X 还在打它。
改前的错误结局：① 新占领者按旧 DefendID 被拉进这个空集结后消失（幽灵驻防，即 H5-12694）；② 直接 DelUnit 空集结的话，X 打赢了却被遣返回城，建筑没人占。
现在的处理：空集结按"防守方战败"结算（battleTroopDead），和防守部队全部被打死走同一流程：先删集结，再让 X 正常占领。
触发条件：只在玩家离开地图且他的部队恰好是集结里最后一支时发生。主城被击飞（不跨服）不动建筑防守集结，不会触发；玩家也不能手动召回防守集结里的部队。属罕见情况，但必须在测试服专门验证。

涉及玩法：王座战（含跨服王座战）、联盟战龙巢、泰坦宝库、冰髓争夺战、GVG、要塞、埋骨之地、阵营中心、远征火车等所有建筑驻防。
