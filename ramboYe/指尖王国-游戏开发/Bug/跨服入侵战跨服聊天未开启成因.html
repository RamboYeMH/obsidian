五、原因与处理方案（已确认缺陷）

业务环节问题描述定性
问题点 1：door1 每次请求同步查库（ctl_match_king_war.go:221） OnCrossGetZvzMatchResultReq 在单协程中每次同步调 zvzmatch2.LoadMeta 查 MongoDB，117 服同秒请求耗时 10.5s，致后 49 服必现 5s 超时（A）。 服务端性能与并发缺陷（P1）
问题点 2：超时无重试且 CrossMatchID==0（ctl_king_war.go:205, 545） crossGetServerInfoCb 超时直接 return 无重试，既导致 8 个最小服未建房，又使 49 个超时服 CrossMatchID==0，王座战结束将误发单服排行奖（A）。 服务端逻辑与发奖缺陷（P1）
问题点 3：客户端空房间 ID 误显「已开启」（CrossServerKingdomMainWidget.cs:538） SetMessageItem() 在 SelfCrossServerActvChatRoomID == null 时激活 not_have_chat_go 展示静态文本「跨服聊天频道已开启！」（A）。 客户端 UI 缺陷（P3）

修复与处理方向

  • P0 线上立即恢复聊天室：切勿在超时服（744、747）直接跑指令；请在已缓存列表的同组服 755 服（恢复 747/751/752/755）、829 服（恢复 744/829/832/872）、837 服、853 服、868 服各执行一次 createcrosactvroom。
  • P1 线上阻断误发奖并修复根因：王座战结算前让 49 个超时服重拉一次匹配信息补齐 CrossMatchID；代码移除 ctl_match_king_war.go:221 同步查库并在 ctl_king_war.go:545 增加超时重试。
