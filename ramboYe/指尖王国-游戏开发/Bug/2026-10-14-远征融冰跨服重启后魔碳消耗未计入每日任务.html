是服务器 bug。融冰部队在路上时 cross1009 重启了，部队上记录的魔碳消耗在重启时丢失。到达后服务器按 0 魔碳结算，于是每日任务没计数，魔碳消耗奖励也没发，已扣的魔碳也没退。

时间线（北京时间）

  1. 10:59:42融冰部队出发，game496 扣除魔碳
  2. 11:00:55cross1009 收到 SIGTERM 重启（server closing down）
  3. 11:01:03cross1009 重新加载地图和部队，到 11:01:13 结束
  4. 11:01:09玩家下线
  5. 11:01:13融冰部队到达（PTroopMeltingIceArrive），融冰进度正常增加
  6. —没有魔碳消耗奖励，没有 M2PSuccessMeltingIce，每日任务没推进

旁证：这个玩家其他几次正常的到达后面，都会跟一条 AddExpCampTrainPlayerContribute（魔碳奖励里的贡献道具自动使用），这一次没有。

原因

  1. 每日任务的“消耗魔碳”不在出发扣费时计数，要等融冰部队到达后，由 playerTroopMeltingIceCb 结算。
  2. 结算时用 calcMagicCarbonCost 算魔碳消耗，数据来自 troop.BatCtx().GetCosts()。
  3. BatCtx 不落库（battleCtx *BatCtx `bson:"-"`）。重启加载部队时，InitBattle 会新建一个空的 BatCtx，消耗记录 Costs 就丢了。
  4. 融冰次数 OriginMarchExtra 是落库的，所以融冰进度还在。但魔碳消耗算成 0 后，paidUse = 0，这次融冰全部被当成免费次数。
  5. effectiveCarbon = 0，grantCarbonReward 没调用，M2PSuccessMeltingIce 没发出，任务 EventBfMeltingIceCarbonConsume 也就没计数。
// game/wmap/internal/ctl_battlefield_melting_ice.go totalCarbon := calcMagicCarbonCost(troop, troopId) // 重启后 Costs 为空 → 0 ... if effectiveCarbon > 0 { // 不满足 wmap.grantCarbonReward(playerID, effectiveCarbon) // 内含 M2PSuccessMeltingIce }

修复建议

  • 把付费魔碳量存进落库字段不要只放在 BatCtx.Costs 里。可以在 PlayerTroop 上加 MeltingIceCarbon，或者放进 OriginMarchExtra，到达和退费时都从这里读。
  • 一起修退费逻辑refundExcessMeltingIce 和 emptyCostReturnExtra 也依赖这份消耗数据。重启后同样会退错：本该退魔碳，结果退成了免费次数。
  • 排查其他受影响玩家10:59~11:01 之间出发、重启后才到达的融冰部队都可能受影响。可以用 cross1009 在 11:01:03 之后的 PTroopMeltingIceArrive 日志，对照 game496 的扣费记录筛出名单，再补发魔碳、奖励和任务进度。
