部队首次到达王座时攻击失败、被召回，但没有从王座的 Attackers 列表移除。40 秒后另一支防守部队退出，触发 kingWarAutoOccupy，把这支正在回城的部队直接拉成了驻防（AddDefender），回城行军却没有停止。它到家走 PTroopRtCity，不会退出王座，于是驻防计时记录里永久留下了它的 ID。之后该玩家每次退出都结算 0 分钟，任务卡在 7/30。

结算机制

王座占领时长不是按 tick 累加，而是在部队退出王座时一次性结算：

  • AddDefender：玩家第一支部队进驻时记录 DefenderEnterTime[玩家].EnterTime，之后进驻的部队只追加到 Troops。
  • RemoveDefender：从 Troops 中移除；只有 len(Troops)==0 时才返回 EnterTime，否则返回 0。
  • handleCrossServerActivityStats：EnterTime > 0 才按 (now-EnterTime)/60000 分钟发 PqThroneCity 活动事件；EnterTime ≤ 0 直接返回。

日志结论对照代码

  • KingWarCtx 只在 executeThroneAttack（ctl_king_war.go）里设置；本次在它之前的 getOrCreateKingWarDefender 就失败返回了。
  • 召回时 giveUpTroopBattle（ctl_march.go）只在 GetKingWarCtx() != nil 时调用 KingWar.CancelAttack，所以部队留在 Attackers。
  • kingWarAutoOccupy 对 Attackers 里仍在地图上的部队调用 KingWarOccupyPTroop → Arrive(ActDefend) → AddDefender，不检查行军状态，也不停止行军。
  • 回城行军到家走 PTroopRtCity，不调用 giveUpDefend / kingWarExit。
  • kingWarExit0 用 getTroopOwnerID 从地图取 owner，部队不在地图上时为 0，RemoveDefender(id, 0) 找不到 DefenderEnterTime[0]。

  1. 敌方部队 X 被吞进旧集结，在王座上成了不在地图上的驻防残留。
  2. 本玩家攻击时建集结失败，系统召回，部队留在 Attackers。
  3. 部队在回城途中被 kingWarAutoOccupy 拉成驻防。
  4. 回城到家后，这支部队永久残留在本玩家的计时记录里。
  5. 之后每次退出都零结算。

复现步骤

一、稳定复现本玩家的问题（推荐）

敌方残留驻防是时序巧合，很难自然造出来。建议在开发服临时加一个 GM，往王座 Defenders 里塞一个不存在的部队 ID（直接 base.AddDefender(假ID, 0)），模拟线上的残留。

前置：跨服王座战处于战斗阶段；联盟 A（敌方）、联盟 B（玩家 P 和 P2 所在联盟）；P 的主城离王座远一点，保证回城行军有足够时间。

  1. 联盟 A 的部队占领王座 1001，然后用 GM 把 Defenders 改成只有一个假 ID（OccupyUnionID 仍是 A）。
  2. P 派部队 T 攻打王座。预期日志：

代码修复（分支 h5_new_tf_v1052，未提交）

ctl_king_war.go · PTroopArriveThrone（根因）

到达处理失败时调用 wmap.KingWar.CancelAttack(brief)，把部队移出 Attackers，避免回城途中的部队被 kingWarAutoOccupy 拉成驻防。

ctl_playertroop.go · PTroopRtCity

在 DelUnit 之前调用新增的 kingWarExitOnReturnCity：部队回城时只要还挂在任何王座或哨塔的 Defenders 或计时记录 Troops 里，就补走一次 kingWarExit0，正常结算并打 Warn 日志。不论从哪条路径回城，都会在这里收口。本案中它会在 20:59:03 把这支部队正常退出。

kingwar/model/base.go

  • RemoveDefender 加兜底 pruneStaleOccupyTroops：剔除 Troops 中已不在 Defenders 里的部队。它只能处理「Defenders 已删、Troops 还在」的残留，比如本案 23:56:10 之后的状态；部队连 Defenders 都还在时它不起作用，那种情况靠 PTroopRtCity 的补退出。
  • AddDefender 同样剔除；全部剔除后重置 EnterTime，避免沿用上一轮遗留的旧时间。
  • 新增 HasOccupyTroop。

ctl_king_war.go

EnterTime ≤ 0 那条日志加上 playerID。

已知偏差：如果部队战败后先行军回城，补结算的时间点是到家那一刻，会比实际离开王座多算一段行军时间。验证情况：game/wmap/internal/... 编译通过；kingwar 包没有单元测试；未在线上环境验证。
