## 上游触发与召回性质
- 召回是**系统自动召回**：到达处理失败 → `marchingCheckFail` → 玩家部队的 fail 控制器为 nil → `recallPlayerTroop`。玩家没有操作。
- 王座上的敌方残留驻防 `7692424334472598780`（归墟 11329956，下称 X）的成因，已用 game850 日志 + 代码坐实（2026-10-07）：
  1. 20:56:18.143~.155 X 正在和我方旧防守集结 rt `7692382570210332360` 交战；rt 车头主城被击飞，rt 被解散，成员逐个退出。最后一支退出时只做了 `OccupyStop`，**`base.DefendID` 没清零**（只有 GiveUp/Clear/Finish 会清，`model/base.go:75/87/99`）。
  2. `kingWarAutoOccupy` → `KingWarOccupyPTroop(X)` → `Arrive` 走 ActOccupy → `AddDefender(X)` → `pTroopArriveThroneOccupy` 末尾「编队立即加入战斗」：`GetDefendID()` 返回旧 rt 的 ID，而 rt 这时还在地图上（外层 `OnP2MCityKickOut → DisbandRallyTroop` 还在逐个召回成员，还没执行到 `DelUnit(rt)`）→ `AddDefenderIntoRallyTroop(rt, X)`。
  3. `AddDefenderIntoRallyTroop` 里的 `DelUnit(X)` 先 `BattleUnitDel`（`ctl_map.go:1678`）→ `giveUpTarget` → `settleBattle` → `ThroneDefendEnd(rt, true)` → `kingWarRallyDisband(rt, recall:false)`：rt 只剩 X，`AddUnit(X)` 放回地图，同盟不召回，然后 `DelUnit(rt)`。
  4. 嵌套返回后 `DeleteUnitObj(X)` 把 X 从地图删掉。最终 X 不在地图、不在集结，但 `Defenders` 和 `DefenderEnterTime` 都还留着它。
  - 真正触发点：rt 车头 11195874 主城在焦土范围内被打破并击飞 → `OnP2MCityKickOut` → `DisbandRallyTroop(rt, Cancel)`，逐个召回成员时同步触发 `kingWarAutoOccupy`。整个过程在同一帧内完成。
  - 缺陷点：占领清空时不清 `DefendID`；`AddDefenderIntoRallyTroop` 里 `DelUnit` 会嵌套触发集结解散，并把部队放回地图。

## 复现
- 推荐：开发服加临时 GM，往王座 Defenders 塞假部队 ID → P 攻击失败被召回 → 回城途中 P2 占领后召回一支 → T 被 `AddDefender` → 到家后 P 再进出，`enterTime:0`。详细步骤见 HTML。
- 上游残留：多人防守集结被敌方单支部队打退并自动占领，观察该部队是否被塞进旧集结。

## 缺陷点
- `game/wmap/internal/ctl_king_war.go` `PTroopArriveThrone`：攻击失败后部队留在 Attackers（根因）
- `game/wmap/internal/ctl_king_war.go` `kingWarAutoOccupy`：把正在行军、不在王座上的部队拉成驻防，且不停止它的行军（根因）
- `game/wmap/internal/ctl_playertroop.go` `PTroopRtCity`：回城不清理王座驻防记录
- `game/wmap/internal/kingwar/model/base.go` `RemoveDefender`：Troops 全清才结算，漏删一支就永久卡住
- `game/wmap/internal/ctl_king_war.go` `handleCrossServerActivityStats`：EnterTime ≤ 0 时静默返回，日志没有玩家 ID
- 另外两条残留路径：`Base.Finish()` 不清 DefenderEnterTime；`kingWarExit0` 对不在地图上的部队取不到 ownerID
