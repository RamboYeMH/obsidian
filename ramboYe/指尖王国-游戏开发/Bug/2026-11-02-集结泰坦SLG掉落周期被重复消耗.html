集结泰坦：队长的 SLG 掉落周期被每个参战部队重复消耗

版本 v1054 · 发现于 2026-11-02 排查万圣节南瓜时 · yemingheng · 严重度：中

集结打赢泰坦后，结算代码在遍历每个参战部队时，都会用队长的掉落周期掷一次南瓜。N 个部队参战，队长的周期就前进 N 次，而不是 1 次。

后果有两个：

  • 队长「10 只泰坦固定掉 5 个」的保底被打乱。
  • 开了自动补体力的集结成员也能拿到南瓜，而设计上只有队长掉落。

先说「周期」是什么

泰坦南瓜用的是保底掉落：每个玩家每打 10 次，必定掉 5 个，只是落在哪几次是随机的。配置是 SlgDropSwitchCfg 1042（frequency_max=10）和 SlgDropCycleCfg 1042001（frequency=5）。

服务器给每人记两个数：本轮打了几次、掉了几次（MapPlayer.SlgDropCycleRecord）。每次的掉率 = 本轮还剩几次要掉 ÷ 本轮还剩几次可打。前面没掉，后面的概率就越来越高，最后变成 100%，所以一轮一定刚好掉 5 个（computeSlgDrop，game/wmap/internal/ctl_battle_settle.go:661）。

第几次12345678910
掉率5/105/94/84/74/64/53/42/32/21/1
结果（示例）–掉–––掉掉–掉掉

正确的用法：每打死一只泰坦，队长的周期只走 1 格。

问题代码

settleBattleRTroopAtkNTroop，game/wmap/internal/ctl_battle_settle.go:2044 起：

for _, pt := range rallyTroopList {                    // 遍历每个参战部队
    ptOwnerId := pt.GetOwnerId()
    ...
    slgrop := wmap.slgDrop(captainPlayerID, monsterType) // :2058 每个部队都用队长的周期掷一次
    ...
    if wmap.canGetAwards(pt, rallyTroop, npcTroop, joinMax) {
        if ptOwnerId == captainPlayerID {              // :2083 只有队长那一次并入奖励
            assets = append(assets, slgrop...)
        }
        if ausoCostFlag == cspb.NoneSet {
            wmap.AddAssets(ptOwnerId, assets, ...)    // 手动扣体力：成员那次 slgrop 被丢弃
        } else {
            autoCostMap[ptOwnerId].PackSetAwards(slgrop) // :2098 自动补体力：slgrop 发给成员本人
        }
    } else {
        autoCostMap[ptOwnerId].PackSetAwards(slgrop)     // 超出参与次数上限的分支同样会发
    }
}

自动补体力的成员这份 SlgDrop，在 play 侧 OnMapToPlayReportAssert（game/play/internal/ctl_map.go:74）扣体力成功后，会通过 append(assets, req.Extra.SlgDrop...) 真正发到账。

例子：3 人集结连打 4 只泰坦

队长 A，成员 B、C。每打死一只泰坦，A 的周期被掷 3 次。下面是 A 的一整轮（10 格），沿用上面示例的命中位置：

#1A第1只–
#2B第1只🎃
#3C第1只–
#4A第2只–
#5B第2只–
#6C第2只🎃
#7A第3只🎃
#8B第3只–
#9C第3只🎃
#10A第4只🎃
A 队长自己的部队 B 成员 C 成员 🎃 这一格掉了南瓜
正确行为4 只泰坦只该用掉 A 的 4 格，全部归 A。
实际：A打到第 4 只就把这一轮 10 格用完了（第 4 只 B、C 那两格算进下一轮）。A 自己只分到 4 格，拿到 2 个。
实际：B、C 的 3 个手动扣体力 → 直接丢掉；自动补体力 → 发给 B、C。

影响

  • 队长的长期平均不变：每格平均 0.5 个，队长每只泰坦分到 1 格，平均还是 0.5 个/只。但保底失效，可能连续很多只都不掉。玩家会反馈「多人集结很久不出南瓜」。
  • 自动补体力的成员白拿南瓜：违背「集结只有队长掉落」（:2083 注释）。而且用的是队长的周期，不占成员自己的，成员的周期不动。
  • 手动扣体力的成员：那几格掷出的南瓜直接浪费，谁也拿不到。
  • 不只影响南瓜：所有 monster_type 含 2 的 SlgDropSwitchCfg 掉落规则都受影响。

修复建议

把队长的掉落移到循环外，每只泰坦只掷一次，只发给队长；循环里成员的 slgrop 从空列表开始（成员自己的秘钥、回归掉落照常追加）。

captainSlgDrop := wmap.slgDrop(captainPlayerID, monsterType) // 每只泰坦只掷一次
for _, pt := range rallyTroopList {
    ptOwnerId := pt.GetOwnerId()
    ...
    var slgrop []*cspb.TypIDVal
    if ptOwnerId == captainPlayerID {
        slgrop = gdconf.DeepCopyTypIDValList(captainSlgDrop)
    }
    ...
}
  • 要确认的设计点：自动补体力的成员到底该不该掉南瓜。如果策划本来就想让他们掉，就该用成员自己的周期（slgDrop(ptOwnerId, …)），不能共用队长的。
  • 队长自动补体力时，掉落走 autoCostMap[captain].SlgDrop，修改后这条路径仍然只发一次，不会重复。
