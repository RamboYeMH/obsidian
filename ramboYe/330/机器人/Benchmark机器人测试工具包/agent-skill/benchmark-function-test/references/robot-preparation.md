# 机器人供给与前置条件

无可用目标、需要创建机器人或需要准备业务条件时读取。先查询授权环境，不能把工具故障当作没有机器人。

- 默认自动供给：先用 `list_test_targets` 查询授权测试环境。存在 `available=true` 目标则复用；查询成功且确认没有可用目标时，由 Agent 自动预览并创建最小所需批次，单角色测试默认 1 个，不要求用户先去页面创建或启动机器人，不重复询问是否创建。
- 必须区分空结果与故障：连接失败、鉴权失败、自测试关闭、环境未获允许、查询被截断或目标筛选不明确，都不能作为创建依据。空列表本身不能证明环境被允许；沿用已确认的测试环境及策略，不能靠不断创建来修复环境配置问题。
- 创建前读取 `get_robot_management_spec`，自动确定环境内的候选 ID、国家和语言，优先沿用已有约定，然后调用 `preview_robot_batch`。没有既定 ID 时可以选择最小批次的候选正整数并通过预览检查冲突，不把技术参数填写转交给用户。
- 预览确认待创建 ID 后，以相同参数调用 `create_robot_batch`（`batch` 参数对象和 `confirm=true`）。冲突时先重新预览，不覆盖、不接管活跃或被暂停的机器人。查询后出现忙碌竞争时先复核原因；不能通过换机器人绕过已触发的限流或尝试预算。创建响应丢失时用原 ID 重新预览核实，不盲目换一批创建。
- 创建后对返回的精确 ID 调用 `list_test_targets`。可用则自动编排已有登录/角色创建、准备和测试 Block，并调用 `run_block_draft` 启动；`offline_wait` 是正常待执行状态，不要求用户手动上线。创建成功但目标仍不可见或不可用时，停止继续创建，定位环境过滤、租约或其他原因并报告。
- 创建的是机器人主档，不代表角色已经创建、登录或满足玩法条件。通过实际登录和准备结果确认后续状态。通常不需要画像；画像不能代替等级、材料或玩法状态。运行实例未提供创建工具时明确指出尚未部署的入口，不把“源码已实现”当作可调用。
- Agent 按当前代码和实际配置拆出前置依赖，逐项标记为已满足、可通过已有 Block/业务协议准备、可通过已授权 GM 准备、或缺少能力。按依赖顺序编排准备，准备后读取状态或用原有 Assert 核验，再执行目标操作。
- 优先复用经核对的准备 Block。`exec_gm_commands` 是现有 LocalLogic，读取 `gm_commands` 字符串数组及可选 `gm_sleep_ms`，需真实登录玩家和现有环境授权。命令及参数从当前 GM 注册/实现和配置核实，不能凭名称猜测；示例 Block 的批量初始化命令不能不加分析地照搬。
- 现有 GM/协议足够时由 Agent 完成准备，不让用户手动配置。如果属于临时战斗状态、跨角色协作或其他无现成操作可达的条件，明确缺少哪一步；不宣称能自动构造任意存档，不改机器人引擎或开放任意数据库写入。
