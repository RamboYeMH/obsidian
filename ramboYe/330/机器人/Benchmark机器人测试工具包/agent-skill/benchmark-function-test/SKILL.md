# 使用现有 benchmark 测试功能

Agent 决定用例、前置条件、预期和业务结论；benchmark 执行并返回事实。用户只需指定功能或函数，不要求填写 Block、画像或选择器。

## 边界与停止条件

- 不修改 benchmark 启动、调度、机器人执行器、断言结构、存档或游戏逻辑，不新增 DSL、测试判定或幂等体系。确有调用缺口时只补必要 MCP 适配。
- 先确认运行实例提供的工具及已授权测试环境；源码有实现不等于实例已启用，不猜线上目标。测试授权不自动涵盖部署或生产写入。
- 保持环境、租约、请求和尝试预算，不换机器人或草稿绕过限额。启动响应丢失时结果未知，不重发；已知 Run ID 用 collect 续查。
- 业务预期执行前确定，不能按实际响应修改预期求通过。只有明确编排错误才局部修正，静态修订建议最多 3 轮，无进展提前停止。

## 默认工作流

1. **定位与复用**：按本机已配置的资料目录查领域索引及命中资料，跨功能查共同前置能力；未配置可复用资料时从当前源码自主发现。若使用 Obsidian，按 `AI工具链/Benchmark功能测试/` 组织；不假定固定用户目录。函数先追溯实际可达入口。旧资料仅供定位，协议通过当前 MCP 核对，实际配置与角色状态实时查询；本地源码不等于部署版本，开发 TSV 不代替实际配置。
2. **选择目标**：用 `list_test_targets` 查询目标和预算。`available` 只表示角色可复用；有 `can_start` 时同时核对它、`attempts_remaining` 和 `next_allowed_at`。`offline_wait` 是正常待执行状态，查询快照不预留额度。旧实例缺少新字段时不能当作零额度，也不能把 available 当作已通过限额检查。查询成功并确认授权环境无可用目标时自动供给最小批次。工具故障、环境被过滤或自测试关闭不能作为创建依据；无目标需创建时按需读取机器人供给说明。
3. **规划**：未指定方向时按适用性选择正常路径、关键拒绝条件、边界、状态/资源变化、重复调用和异步最终状态，不默认穷举或压测。先列准备、目标操作、预期及依据，区分业务规则、配置与仅按实现生成的回归；准备后核验，准备不能代做被测操作。
   - 等级、阶段、关卡等有序配置不能只挑当前等级连续跑几次并称为功能覆盖。先检查可用配置的完整范围、断档和字段关联，再结合代码分支找规则变化点（消耗/解锁/上限等）及前后边界，选代表等级执行机器人用例；普通等级只有在逻辑分支或关键配置不同时才增加运行。
   - 配置静态检查与机器人执行回答不同问题：前者可覆盖可查询配置范围，后者验证代表路径的运行行为。说明各自数据源与部署版本；开发配置不能冒充部署配置，缺少部署查询时明确标注。
   - 同一功能还应按代码和配置适用性检查开放条件、最高级拒绝、关键资源不足及失败后状态/扣费。自动购买、持久化、活动/战力联动只在属于目标范围且存在可观测依据时纳入。预算受限时先跑高风险分支，报告实际覆盖和未覆盖项；少量冒烟结果不写成“系统测试完成”。
4. **编排**：查当前 `get_flow_spec`，用 search_context/get_block 找已有能力，get_protocol 批量取已确定需要的协议。优先组合小 Block，缺能力才补，内部逻辑不同才克隆。关联状态与跳转一批提交原生 operations，编辑已返回 validation，不重复校验。新子 Block 须保存且能被执行路径加载，顶层可保留草稿；不覆盖已有共享 Block。
5. **执行取证**：使用现有客户端 create-draft/apply-draft/run/collect/read-evidence，按当前 revision 局部提交，冲突不自动覆盖；授权测试传 confirm=true，不逐工具重复确认。固定轮询、分页和原始响应保存交给客户端，不由 Agent 逐次重复操作。详细 Trace 主要在子进程结束后回放。
6. **分析返回**：对照事前预期、实际执行分支和证据判断。流程 succeeded 不等于业务通过；failed 可能是预期的负向错误码。区分定义错误、准备失败、执行故障、预期不符、阻塞和未知，不能把事件数当用例数。缺失、截断和未覆盖项明确披露；内部链路只据可关联证据分析，不承诺不存在的追踪能力。

独立且已知的只读查询可以批量或并行；有依赖的查询按顺序，不为减少调用猜参数。准备命令、GM 和 LocalLogic 从当前实现核实，不凭名称或旧模板直接执行。缺少准备能力时说明具体缺口，不扩展为任意存档写入。

## 按需读取，不全量加载

| 场景 | 资料 | 用途 |
|---|---|---|
| 编写/调用 Block、使用客户端或执行异常 | [客户端与 Block 编排](references/client.md) | 小 Block 契约、克隆/修改、调用加载、命令、证据与续读 |
| 无目标需创建，或需要 GM/业务准备 | [机器人供给与前置条件](references/robot-preparation.md) | 查询/预览/创建/复查、状态核验与准备边界 |
| 即将启动真实机器人测试 | [运行前核对](references/run-preflight.md) | 角色数量、运行数据契约、断点续跑与限额处理 |
| 命中复用资料需核对，或确有新增信息需保存 | [轻量资料复用](references/reuse.md) | 领域关联、失效核对、最小增量记录 |

客户端已提供固定操作，不新增脚本复制这些能力。具体业务拆解、用例选择、预期依据和是否可复用由 Agent 判断，不交给规则脚本猜测。

## 结果与轻量沉淀

测试结果默认只在对话中返回。Markdown 报告、结果汇总和 HTML 仅在用户明确要求时生成，不自动归档每次运行。

可复用能力资料与测试结果报告分开：只记录确有复用价值的入口、操作契约、限制及最小验证依据，不把整次测试结果包装成能力笔记。客户端的私有原始证据仍保留以便续查，不属于用户报告。无新增信息不写文档、不刷新日期。首次积累能力资料优先一份精简笔记，领域作标签或索引分组；实际跨功能复用时才拆公共能力，索引仅在入口变化时维护。逐项标记未验证/已验证/失效，不把临时草稿或消失的证据当长期产物。保存失败说明未保存，不承诺回合结束后后台继续写。资料落 Obsidian 并遵守文件权限；评估优化时将资料维护耗时计入，不凭输出变短推测 token 或速度收益。
