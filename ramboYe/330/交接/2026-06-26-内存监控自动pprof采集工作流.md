# 内存监控 + 自动 pprof 采集工作流

## 背景

cross1012 在 22:00 发生内存瞬间上涨（IceContest 阶段结束时批量处理部队导致 zap buffer 积累），需要一个能在内存持续上涨时自动触发 pprof 采集的守护脚本。

## 脚本位置

`/home/wenyu/Documents/330gs/scripts/mem_watch.py`

## 技术方案

### 数据源

- **Grafana**: `http://106.53.123.224:3000`（auth: admin:J6K2y6Cx）
- **Datasource**: id=1, Prometheus，地址 http://localhost:9090
- **内存 Metric**:
  ```
  namedprocess_namegroup_memory_bytes{groupname=~"cross_.*", memtype="resident"}
  ```
- 实例标签为 `groupname`，格式 `cross_1012`（注意有下划线）
- Dashboard "游戏进程信息"（uid: dey7orlq7sg74b），面板：resident memory

### 检测逻辑

- 每 30s 查一次 Prometheus（通过 Grafana datasource proxy）
- 每实例维护 5 分钟滑动窗口（10 个采样点）
- **触发条件（AND）**：
  1. 窗口内全部相邻采样点单调递增
  2. 总增长率 ≥ 5%
- 触发后 30 分钟冷却，避免同一事故重复告警

### pprof 采集

- **方案 B（已选）**：调用 `claude -p "..."` CLI，让 Claude Code 使用 game-mcp `pprof_save` 工具采集
- 实例名归一化：`cross_1012` → `cross1012`（去掉下划线，供 pprof_save 使用）
- pprof 端口推导：`cross{N}` → `28000 + N`（cross1012 → 29012）
- 文件保存至 `/tmp/mem_watch_pprof/`

### 运行方式

```bash
# 守护进程
nohup python3 scripts/mem_watch.py \
  --ding "https://oapi.dingtalk.com/robot/send?access_token=xxx" \
  > /tmp/mem_watch.log 2>&1 &

# 测试连通性
python3 scripts/mem_watch.py --test-grafana

# 低阈值验证逻辑（不实际采集）
python3 scripts/mem_watch.py --min-growth 0.01 --dry-run
```

## 踩坑记录

1. **groupname 标签有下划线**：Grafana label 是 `cross_1012`，不是 `cross1012`；pprof 端口推导和 game-mcp 实例名都需要去掉下划线
2. **Grafana API 认证**：支持 `"user:pass"` Basic Auth 和 `"Bearer token"` 两种格式，代码里统一走 `api_key` 参数
3. **datasource proxy 路径**：`/api/datasources/proxy/{id}/api/v1/query_range`（不是 `/api/ds/query`）
4. **game-mcp 不能直接从 Python 调用**：它是 MCP 协议，只能通过 Claude Code 会话使用，所以采集路径是 `subprocess.run(["claude", "-p", prompt])`
