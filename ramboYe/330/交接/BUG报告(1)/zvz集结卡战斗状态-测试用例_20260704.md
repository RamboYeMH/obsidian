# 联盟战龙巢集结卡战斗状态 — 测试用例

## 测试目标

验证联盟战争夺传送塔/龙巢过程中，战斗结束后玩家战斗状态能正确清除，部队能正常召回。

## 环境准备

| 条件 | 说明 |
|------|------|
| 区服 | 任意测试服 |
| 联盟 | 联盟 A（防守方，占领龙巢）、联盟 B（攻击方） |
| 龙巢城 | 1 座，联盟战区域内 |
| 双方玩家 | 联盟 A ≥ 3 人（防守护塔/加入集结），联盟 B ≥ 3 人（各派编队攻击） |

---

## 用例 1: 攻击方多编队取消攻击，战斗状态正确清除

> 对应缺陷：`giveUpTarget` 不调用 `battleEnd`（`ctl_battle.go:694-704`）

### 前置条件

1. 联盟 A 占领龙巢城，防守集结已形成
2. 集结中包含联盟 A 玩家 PA1、PA2 的部队

### 步骤

| # | 操作 | 预期结果 |
|---|------|---------|
| 1.1 | 联盟 B 玩家 PB1 派出编队 L1 攻击龙巢城 | L1 到达后进入战斗，集结的 `CurTarget` = L1 |
| 1.2 | 联盟 B 玩家 PB2 派出编队 L2 攻击龙巢城 | L2 到达后进入战斗 |
| 1.3 | 联盟 B 玩家 PB3 派出编队 L3 攻击龙巢城 | L3 到达后进入战斗 |
| 1.4 | **先召回** L2（后到达的编队）| L2 正常回城，战斗状态清除 ✓ |
| 1.5 | **再召回** L3（后到达的编队）| L3 正常回城，战斗状态清除 ✓ |
| 1.6 | **最后召回** L1（第一个到达的编队）| L1 正常回城，战斗状态清除 ✓ |
| 1.7 | 检查集结状态 | 集结正确解散或保持空闲状态，**无卡战斗** ✓ |

### 变体（不同召回顺序）

| # | 操作 | 预期结果 |
|---|------|---------|
| 1.8 | **新环境**，PB1、PB2、PB3 再次攻击 | — |
| 1.9 | **先召回** L1（第一个到达）| L1 正常回城 ✓ |
| 1.10 | **再召回** L2、L3 | **【关键】** L2、L3 正常回城，战斗状态清除 ✓ |
| 1.11 | 检查 PB1、PB2、PB3 的编队状态 | 三队均处于"空闲/回城"状态，**无卡战斗** ✓ |

### 验证点

- [ ] `giveUpTarget` 日志中，最后一个攻击方放弃时，必须有 `battleEnd` 调用
- [ ] 集结的 `CCityDefendEnd` 日志 `InBattle:false` 后必须跟随 `解散联盟战集结`
- [ ] 回城后玩家编队状态为 `TroopStateIdle`

## 用例 2: 防守方部队在持续战斗中能正常召回

> 对应缺陷：`recallPlayerTroop` 条件过严（`ctl_map.go:1890-1892`）

### 前置条件

1. 联盟 A 占领龙巢城，防守集结已形成
2. 集结中包含玩家 PA1 的 2 支部队（模拟线上玩家 6007963 场景）

### 步骤

| # | 操作 | 预期结果 |
|---|------|---------|
| 2.1 | 联盟 B 玩家 PB1 派出编队攻击龙巢城 | 集结进入战斗 |
| 2.2 | **在战斗中**，PA1 尝试召回自己的 2 支部队 | 部队开始回城，战斗状态清除 ✓ |
| 2.3 | 检查 PA1 的部队位置 | 部队不在集结中，正在返回 ✓ |
| 2.4 | PB1 的编队被击败 | 集结战斗正常结束 ✓ |
| 2.5 | 检查集结和所有参战部队状态 | 无残留战斗状态 ✓ |

### 变体（持续攻击场景）

| # | 操作 | 预期结果 |
|---|------|---------|
| 2.6 | **新环境**，PA1 的部队加入防守集结 | — |
| 2.7 | PB1 攻击 → PB2 攻击 → PB3 攻击（连续 3 波） | 集结持续战斗中 |
| 2.8 | 在第 2 波攻击进行中，PA1 尝试召回 | **【关键】** 部队应能召回，不被 `GetCurTarget() != nil` 拦截 ✓ |
| 2.9 | 等待所有攻击结束 | 集结正常解散，PA1 部队已回城 ✓ |

### 验证点

- [ ] `recallPlayerTroop` 不因 `GetCurTarget() != nil` 被跳过（日志无"找到了玩家部队，在集结"的循环）
- [ ] 玩家不再需要反复查询部队位置来触发修复
- [ ] 召回后部队状态为"回城中"或"空闲"，不显示"战斗中"

## 用例 3: 集结解散-重建循环中玩家部队不被卡住

> 对应缺陷：`getOrCreateDefender` 无限循环重建（`ctl_union_war.go:1983-2005`）

### 前置条件

1. 联盟 A 防守龙巢城，防守集结多次解散和重建
2. 联盟 B 持续派部队攻击

### 步骤

| # | 操作 | 预期结果 |
|---|------|---------|
| 3.1 | 让联盟 B 以 30s 间隔连续派 5 支编队攻击龙巢城 | 集结持续处于战斗-结束-重建循环 |
| 3.2 | 在第 3 波攻击进行中，PA1 召回自己的部队 | 部队正常回城 ✓ |
| 3.3 | 第 3 波结束后集结解散 | **【关键】** PA1 的部队不在重建的集结中 ✓ |
| 3.4 | 第 4 波攻击到达，集结重建 | 新建的集结**不含** PA1 的部队 ✓ |
| 3.5 | 所有攻击结束后检查 | 无部队卡在集结中，无残留战斗状态 ✓ |

### 验证点

- [ ] 解散日志（`解散联盟战集结`）中正确包含所有应释放的部队 ID
- [ ] 重建日志（`创建防守集结部队`）中不包含已召回的部队
- [ ] `龙巢防守战结束` 日志中 `InBattle` 状态转换正确：`true → false`

## 测试数据收集

每次测试记录以下日志关键信息：

```
# 需要 grep 的日志 tag：
- "settarget >>>>>>>>joinpassive"     # 进入战斗
- "GiveUpTarget settle"               # 放弃目标
- "龙巢防守战结束"                     # 战斗结束回调
- "解散联盟战集结"                      # 集结解散
- "防守部队不存在，创建集结"             # 集结重建
- "创建防守集结部队"                    # 集结创建
- "找到了玩家部队，在集结"              # 玩家部队被困
- "recallPlayerTroop"                 # 被召回
```
