# BUG：英雄试炼双活动临界点问题

## 现象

当服务器开服时间恰好为 `2026-06-19 00:00:00` 时，英雄试炼同时出现两个活动：
- 老活动 1010001
- 新活动 1010002

按设计应仅开启其中一个。

## 复现步骤

1. 设置服务器开服时间为 `2026-06-19 00:00:00`
2. 进入游戏查看英雄试炼活动列表
3. 观察到两个活动同时存在

## 根因分析

### 活动判断链路

活动开启经过两套独立检查，**没有任何活动间互斥机制**：

```
checkState()        → OpenDayLimit / OpenDayMax（相对开服日期的天数限制）
triggerActv()       → cfg.CheckServerOpenTime()（绝对时间戳比较）
```

两套检查使用了不同的基准时间戳（不一致设计）：
- `checkState()` 用 `GetServerOpenDayStartTs()` = 开服当天**零点**
- `CheckServerOpenTime()` 用 `GetServerOpenTs()` = 实际开服**毫秒时间戳**

### `CheckServerOpenTime` 核心逻辑

```go
// gdconf/conf_actvonline_ext.go
func CheckServerOpenTime(specialType int32, specialVal string) bool {
    switch specialType {
    case ActvOpenTsTriggerGEAbs: // type=5：开服时间 >= 绝对值
        return conf.GetServerOpenTs() >= util.Time2Ms(t)
    case ActvOpenTsTriggerLTAbs: // type=6：开服时间 < 绝对值
        return conf.GetServerOpenTs() < util.Time2Ms(t)
    default:
        return true  // ← type=0 或未知类型：无条件放行！
    }
}
```

### 触发条件

当 `FirstOpenTs = Time2Ms("2026-06-19 00:00:00")` = T 时：

| 活动 | SpecialType | 条件计算 | 结果 |
|------|------------|---------|------|
| 1010001（老） | **0（未配置）** | `default → return true` | ✓ 开启 ← **BUG** |
| 1010002（新） | 5（GEAbs），val="2026-06-19 00:00:00" | `T >= T` → true | ✓ 开启 |

**根本原因**：活动 1010001 的 `SpecialType` 未配置（值为 0），`CheckServerOpenTime` 对 type=0 直接返回 `true`，导致该活动对所有服务器无条件通过时间检查。2026-06-19 是 1010002 首次激活的日期，两者在此日期产生叠加。

## 修复方案

**配置层修复（推荐）**：给活动 1010001 补上上限：

```
SpecialType = 6（ActvOpenTsTriggerLTAbs）
SpecialVal  = "2026-06-19 00:00:00"
```

含义：仅对 `开服时间 < 2026-06-19` 的服务器开启该活动。

这样两个活动的条件变成 `< T` 和 `>= T`，数学上严格互斥，任何临界点都不会重叠。

## 相关代码位置

| 文件 | 作用 |
|------|------|
| `gdconf/conf_actvonline_ext.go` | `CheckServerOpenTime()` 实现，type=0 的 `default: return true` |
| `game/actv/internal/activity/mgr/trigger.go` | `triggerActv()` 调用 `CheckServerOpenTime`；`checkState()` 用不同时间戳 |
| `game/actv/internal/activity/mgr/actv_msg.go` | `OnActvCalendarReq` — 日历展示同样调用 `CheckServerOpenTime` |
| `game/conf/server.go` | `GetServerOpenTs()` vs `GetServerOpenDayStartTs()` 的区别 |

## 附注

- 两套检查使用不同时间戳（`GetServerOpenTs` vs `GetServerOpenDayStartTs`）是一个**设计不一致点**，在开服时间恰好为午夜零点时两者相等，但非零点开服时存在偏差，可能引发其他类活动的临界 bug。
- `CheckServerOpenTime` 的 `default: return true` 设计是一个**隐性陷阱**：任何未正确配置 SpecialType 的新旧活动切换都可能出现叠加。
