## 根因

**`game/play/internal/ctl_lineup.go:3428` (setLineupDataCb BeAttack 回城分支)**

```go
if p.City.BeAttack && in > 0 && !req.IsDelegate && !req.RecallOnly {
    defCnt := p.LineupMgr.LeftSoldiersCount      // 守城被打剩的兵
    curRedif := play.UpdateRedifCount(p)
    totalRedif := defCnt + curRedif
    play.SetSlgCampRedif(p, totalRedif, def.ReasonIDSetRedifIn)  // ① 被打剩的守城兵并入预备兵资产
    ...
    totalRedif = play.UpdateRedifCount(p) + in
    ids, ... := play.toDefenderInfo(p, true)     // ② 用全量预备兵重建守城编队
    play.Cast2Map(... &iproto.P2MChangeTroop{...}) // ③ 发回 wmap 替换战斗中部队
}
```

闭环：① 把被攻击消耗后的守城剩余兵全量并入预备兵 → ② `RefreshDefenderLineup` 用全部预备兵+城内编队兵重建守城编队 (assignSoldiers checkMax=false 不检查上限) → ③ wmap `OnP2MChangeTroop` 执行 `defTroop.RemoveSelfTroop` + `updatePlayerCityDefender` 重建满编部队，同时 `OnChangeTroopRevertDead` 把 DeadCount 死兵返还复活泉。

**效果：战斗中被消耗的伤亡兵 (HurtCount 13M+) 被"重置"回满编前线，死兵还返还。每进出一轮 = 战斗消耗清零。** 正常回城 (非 BeAttack) 走 3469 else 分支只加兵不重置，无此问题。

## 稳定复现步骤 (测试人员补充, 已验证与代码一致)

玩家 a(被攻方), 玩家 b(攻方, 8 支编队攻击)。

1. a 派出 8 支编队出城, 兵营预备兵保持 > 0, 记录预备兵数量
2. a 城防战血量掉到一半, 把 8 支编队拉出城 (→ `AssignSoldier` 1680 行: `left = defCnt+curRedif+curCount-out`, SetSlgCampRedif(left), toDefenderInfo 重建守城编队)
3. 临时编队城防战血量再掉到一半, 8 支编队拉回城 (→ 3428 行: `SetSlgCampRedif(defCnt+curRedif)`, 被打剩守城兵并入预备兵)
4. 临时编队血量再掉一半, 再拉出城, 让 8 支编队把预备兵全带走 → 兵营预备兵=0 → 自动结束城防战
5. 查看预备兵数量: 已刷多出大量

**闭环本质**: 每次"拉回城"走 3428 分支把被打剩的守城兵(defCnt)并入预备兵, 再 toDefenderInfo 用全量预备兵重建守城编队; 每次"拉出城"走 1680 分支再把兵带走。循环中战斗损耗被反复回滚。

## 修复方向

1. BeAttack 回城分支禁止重置守城编队 (仅把回城兵按常规路径加入城内编队)，或
2. 回城时 `SetSlgCampRedif` 不应并入 `defCnt` (守城剩余兵不属于可回收预备兵，应由 wmap 战斗结算)，或
3. BeAttack 期间禁止拖动编队进出城 (客户端+服务端双重校验)。
