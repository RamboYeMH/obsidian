# cross1005 性能排查报告（2026-06-24）

## 环境

- 实例：cross1005（跨服地图）
- 采样：CPU profile 30s + heap profile（game-mcp pprof_save）
- CPU 利用率：**90.03%**，总堆：**2.15 GB**，生命周期分配：**277.81 GB**

---

## CPU Profile Top 热点

| 函数 | flat | cum | 说明 |
|------|------|-----|------|
| `UnitMgr.RangeUnits` | 3.13% | **34.16%** | 每1秒遍历全部战斗单位 × 3 |
| `Unit.OwnerInfo` + `PlayerTroop.OwnerInfo` | 6.26% | **~22%** | 热路径重复构造，触发 GetPlayerCache |
| `exitBattleLogic` | 1.40% | 10.28% | 每秒对所有战斗单位执行 |

| `isGatherResourceLow` | 2.28% | 2.28% | 简单循环，采集 ticker 高频调用 |

### 核心问题 1：`RangeUnits` cum 34.16%

`timerBattleTicker`（1s）→ `RangeBattleUnit` → `RangeUnits × 3`（PlayerTroop + RallyTroop + NpcTroop）。每次遍历走三层间接：`mapUnits[t]` 迭代 → `GetGridByIndex` → `grid.GetEntity` → 接口断言。

### 核心问题 2：`OwnerInfo()` 每次重新构造

`Unit.OwnerInfo()` 调用 `NewOwnerInfo` → `cache.GetPlayerCache(id)`（sync.HashTrieMap.Load，flat 4.5%）。典型低效：

```go
// unit_mgr.go:128 — 全量遍历只为取 ID
if unit.OwnerInfo().ID == playerID { ... }

// unit_mgr.go:154 — 同一单位调用两次
if mapUnit.OwnerInfo().Type == cspb.TypePlayerOwner && mapUnit.OwnerInfo().ID == playerID { ... }
```

## 重点专项：GetD2GatherCfg 19.70 GB 根因

### 根因：`map[interface{}]interface{}` key boxing

`CsvConf.Index` 类型为 `map[interface{}]interface{}`。调用 `csv.Index[int32]` 时，`int32` 必须 boxing 成 `interface{}` 作为 map key → **每次堆分配**。

### 热路径：一次 Settle 调用 GetD2GatherCfg 3 次

```go
// map_gather.go:349
gathered := gp.SettleOnce(elapseMs, gp.BaseSpeed(), ...)   // ① GetD2GatherCfg

// map_gather.go:364 — tlog.Infof 参数 eager 求值，即使生产也执行
tlog.Infof("... baseSp:%+v ...", ..., gp.BaseSpeed(), ...)  // ② 重复调用！

// map_gather.go:366
if !gp.IsUnlimited() { ... }   // ③ → gather.go:380 → GetD2GatherCfg
```

### 构造时机浪费

`NewNpcGather(cfg *D2GatherCfg)` 构造时已有 cfg，但未缓存。后续每次 `BaseSpeed()` / `ShouldSave()` / `IsUnlimited()` 都重新查找。

## 已落地改动（2026-06-24）

### map_gather.go:SettleRapidly

提取局部变量消除重复调用：

```go
// before: gp.BaseSpeed() 调用 2 次，gu.OwnerInfo() 调用 2 次
// after:
baseSpeed := gp.BaseSpeed()
gathered := gp.SettleOnce(elapseMs, baseSpeed, gatherCtx.Speedup)
// ...
ownerInfo := gu.OwnerInfo()
gp.Record(ownerInfo.Owner.ID)
tlog.Infof("... baseSp:%+v ... owner %v ...", ownerInfo.Owner, ..., baseSpeed, ...)
```

每次 settle 节省 1 次 `GetD2GatherCfg` boxing + 1 次 `OwnerInfo()`/`GetPlayerCache`。

### unit_mgr.go:GetTroopByPlayerID

```go
// before: GetMapUnitsByType（构建新切片）+ OwnerInfo().ID（GetPlayerCache）
// after:
mu.RangePlayerTroop(func(troop *mtroop.PlayerTroop) {
    if troop.Owner.ID == playerID {
        es = append(es, troop)
    }
})
```

消除 34.67GB 切片分配 + 彻底跳过 `OwnerInfo`/cache lookup。

### unit_mgr.go:GetUnitByPlayerID

```go
info := mapUnit.OwnerInfo()
if info.Type == cspb.TypePlayerOwner && info.ID == playerID { ... }
```

合并双次调用为一次。

### P0 已完成：GatherAble 缓存 d2Cfg

**改动文件：** `gather.go` / `npc_gather.go` / `bf_gather.go`

```go
// gather.go — 新增字段 + 懒初始化访问器
type GatherAble struct {
    // ...
    d2Cfg *gdconf.D2GatherCfg `bson:"-"` // 配置缓存，避免每次查表
}

func (ga *GatherAble) D2Cfg() *gdconf.D2GatherCfg {
    if ga.d2Cfg == nil {
        ga.d2Cfg = gdconf.GetD2GatherCfg(ga.CfgID)
    }
    return ga.d2Cfg
}

func NewGather(cfgID int32, ...) *GatherAble {
    ga := &GatherAble{CfgID: cfgID}
    ga.d2Cfg = gdconf.GetD2GatherCfg(cfgID)  // 新建时立即填充
    // ...
}
```

`IsUnlimited`、`SettleDrop`（gather.go）、`BaseSpeed`/`ShouldSave`（npc_gather.go）、`BaseSpeed`（bf_gather.go）全部改用 `ga.D2Cfg()`。

**DB load 路径**：懒初始化，首次访问自动重建，无需改 loader.go。  
**deepcopy**：`*out = *in` 浅拷贝指针，config 只读，正确。  
**预计效果**：消除 ~90% 的 19.70GB GetD2GatherCfg 分配。
