## 二、问题描述

**玩家反馈**：区服 293 玩家 3862086（炎黄懒大王）反馈，2026-06-16 晚参加冰髓争夺战后发现兵力减少约 40 万，从约 170 万降至 129 万，怀疑系统丢兵。

**日志核查结论**：确认为服务端 Bug，非玩家误操作，约 40.7 万伤兵因并发结算时版本号竞争被永久丢弃。

---

## 三、根本原因

### 触发链

```
21:09:38  编队出征跨服冰髓图，参与大型防守对战（joinpassive）
          ↓
21:59:50  防守激烈，每秒结算：left:231739 hurt:~2M dead:77
          ↓
22:00:00  toDefenderInfo version:967  left:0  useTotal:369960
          toDefenderInfo version:968  left:7  useTotal:635896
          toDefenderInfo version:969  left:6  useTotal:842992
          （TmpLineupVersion 快速推进至 971）
          ↓
22:00:01  冰髓强制结算，wmap 已无城防 defTroop
          → M2PChangeTroopFail(version:967, HurtCount≈10万) 到达
          → M2PChangeTroopFail(version:968, HurtCount≈10万) 到达
          → M2PChangeTroopFail(version:969, HurtCount≈10万) 到达
          → M2PChangeTroopFail(version:970, HurtCount≈10万) 到达
          ↓
setLineupDataFailCb：版本不匹配 (967 ≠ 971) → 直接 return
                                               ← BUG：HurtCount 被丢弃
```

### 关键日志证据

```
[22:00:01] setLineupDataFailCb ignore version 967 971   ← ~10万伤兵丢失
[22:00:01] setLineupDataFailCb ignore version 968 971   ← ~10万伤兵丢失
[22:00:01] setLineupDataFailCb ignore version 969 971   ← ~10万伤兵丢失
[22:00:01] setLineupDataFailCb ignore version 970 971   ← ~10万伤兵丢失
[22:00:01] setLineupDataOkCb addEasterSoldier deadSoldier:93   ← 只有93人永久阵亡
```

### 为什么 HurtCount 不能由新版本覆盖

`toDefenderInfo` 每次调用时执行：
```go
lineupMgr.HurtSoldiersCount = 0   // 强制清零
lineupMgr.TmpLineupVersion += 1
```

导致每个版本的 `HurtCount` 是**该轮独有**的增量伤兵数，不在任何后续 callback 中重复出现。过期 FailCb 被 ignore 后，这些伤兵没有任何补回机制。

同时，版本 971 成功的 `setLineupDataOkCb` 只处理 `DeadCount`（阵亡士兵），不涉及 `HurtCount`（伤兵）。

## 四、修复方案

**文件**：`game/play/internal/ctl_lineup.go`

**修改前**（L3272-3274）：

```go
if req.VersionID != mgr.TmpLineupVersion {
    tlog.Infof("%d redif setLineupDataFailCb ignore version %d %d", req.PlayerID, req.VersionID, mgr.TmpLineupVersion)
    return
}
```

**修改后**：

```go
if req.VersionID != mgr.TmpLineupVersion {
    tlog.Infof("%d redif setLineupDataFailCb ignore version %d %d hurtCount:%d", req.PlayerID, req.VersionID, mgr.TmpLineupVersion, req.HurtCount)
    // 每次 toDefenderInfo 会重置 HurtSoldiersCount，该版本的伤兵不会被新版本覆盖，需单独补回
    if req.HurtCount > 0 {
        play.AddSlgCampRedif(p, req.HurtCount, def.ReasonIDRedifBackHurt)
        curRedif := play.GetRedif(p)
        lineupAllCnt := p.LineupMgr.GetLineSoldierCount()
        tmpLineupCnt := p.LineupMgr.GetTmpLineSoldierCount()
        p.BILogRedifWithCountHome(0, false, 0, 0, curRedif, lineupAllCnt, tmpLineupCnt, req.HurtCount, "城防版本过期补伤兵")
    }
    return
}
```

**修复逻辑**：
- 版本过期时，`SoldiersInfo`（存活兵）**不还原**——新版本已成功上图，战斗结束会正常回城，还原会重复计算
- `HurtCount` **必须补回**——该轮独有数据，不补回则永久丢失
- 使用 `AddSlgCampRedif`（预备兵 Redif）补回，与 `tmplineup not found hurtcount>0` 的处理逻辑一致（L2989）

## 五、影响范围

### 触发条件（需同时满足）

1. 玩家城市正处于**城防战**状态
2. 城防战期间 `toDefenderInfo` 被调用 **≥2 次**（TmpLineupVersion 连续递增）
3. wmap 端拒绝了某版本的 `P2MChangeTroop`（city 消失或 defTroop 消失）

### wmap 返回 FailCb 的场景

| 场景 | 触发条件 | HurtCount 内容 |
|------|----------|---------------|
| flag:1 | wmap 找不到玩家城市 | 本轮增量伤兵 |
| flag:2 | 城防 defTroop 已不存在 | 本轮增量伤兵 |
| flag:3 | 请求 IDs 为空（极少见） | 本轮增量 + 历史累计 |

### 不受影响的功能

- 普通行军出征/回城（`endmarch` 路径）
- 冰髓争夺正常回城（`BattlefieldOther TroopRtCity` 路径）
- 城防战正常结算（版本匹配的 FailCb，代码路径不变）
- 魔物入侵（独立 tmplineup 路径）
- 版本过期 + HurtCount=0 的 FailCb（新增 if 判断，不处理，行为不变）

## 六、测试要点

### 场景 1：回归验证（优先级最高）

**目的**：确认正常城防战流程不受影响

```
1. 玩家 A 攻击玩家 B 的城
2. 城防战正常进行并结束
3. 验证 B 的伤兵正常进医院 / 补回预备兵
4. 验证总兵力 = 战前兵力 - 永久阵亡数
```

### 场景 2：版本竞争验证（复现 Bug 场景）

**目的**：验证修复有效

```
1. 玩家 B 城正被 A 攻击（城防战中）
2. B 在城防战期间快速派兵出征再召回，使 toDefenderInfo 多次调用（TmpLineupVersion 递增）
3. 攻击结束后，触发残留 FailCb 版本过期的情况
4. 查 Kibana 是否有 "城防版本过期补伤兵" BILog
5. 验证伤兵已补回预备兵，总兵力无异常减少
```

### 场景 3：冰髓 + 城防并发（Bug 原场景）

```
1. 玩家出征跨服冰髓图参与防守
2. 同时安排另一玩家攻击该玩家本城（触发城防战）
3. 冰髓结算时（活动结束/22:00），观察兵力变化
4. 修复前：兵力减少且无对应 deadSoldier 记录
5. 修复后：即使触发 ignore，BILog 中应有 "城防版本过期补伤兵"
```

### Kibana 验证关键词

| 日志 | 说明 |
|------|------|
| `setLineupDataFailCb ignore version X Y hurtCount:N`（N>0） | 触发了修复逻辑 |
| `城防版本过期补伤兵` | 伤兵已补回（BILog） |
| `setLineupDataFailCb ignore version X Y hurtCount:0` | 无伤兵，正常跳过 |

## 八、附录：数据流对照

```
正常城防战结算：
  wmap.M2PChangeTroopOk → setLineupDataOkCb → 处理 DeadCount（阵亡）
  wmap.M2PChangeTroopFail（版本匹配） → setLineupDataFailCb → 还原 total + HurtCount

本次 Bug 路径：
  冰髓强制结算 → wmap 城防已结束 → M2PChangeTroopFail(version:967, HurtCount:X)
  → game 端 TmpLineupVersion=971 → 版本不匹配 → return（丢弃 HurtCount）× 4

修复后路径：
  版本不匹配 → HurtCount > 0 → AddSlgCampRedif(HurtCount) → 伤兵补回预备兵
```
