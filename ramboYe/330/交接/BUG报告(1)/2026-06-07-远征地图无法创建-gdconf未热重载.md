# BUG：6/7 23:00 远征/远征前夕地图无法创建

## 故障概述

- **时间**：2026-06-07 23:00:00
- **现象**：actType:155（远征）和 actType:154（远征前夕）的匹配组地图全部静默跳过，未创建
- **影响**：154 台 game 服的联盟本轮无法参与活动

## 根因分析

### 调用链
```
BattlefieldMapCheck (global/internal/ctl_battlefield.go:156)
  → openInfo.Servers[sid].Playbook = 1
  → gdconf.GetExpPlayBookCfg(1) == nil   ← 返回 nil
  → continue  ← 静默跳过，不创建地图
```

### 直接原因
`gdconf.GetExpPlayBookCfg(1)` 返回 nil —— 服务器内存中的 `ExpPlayBookCfg` 表没有 `id=1` 的行。

### 深层原因（经验结论）
**配置大概率已存在于数据库，但 global1 在配置更新后未执行热重载/重启**，`atomic.Value` 中缓存的是旧版本配置表，新增的 `id=1` 行未被加载。

> ⚠️ **通用规律**：遇到任何服务器报 `XxxCfg is nil` 但配置逻辑上应存在时，**优先排查服务器是否热重载**，而非先去查配置行是否存在。

## 修复步骤

1. **立即**：触发 global1 gdconf 热重载，确认 `GetExpPlayBookCfg(1)` 有返回值
2. **补救**：执行 GM 指令重跑 BattlefieldMapCheck（`/gmfixbattlefieldbeforerank`）
3. **长期**：在 `BattlefieldMapCheck` 启动前加配置预校验，发现 playbook 配置缺失时打告警并拒绝，避免静默失败

## 经验沉淀

**通用排查顺序（gdconf/aconf 等配置缓存类问题）**：

1. 查服务器最近重启时间 vs 配置更新时间
2. 触发 gdconf reload，观察报错是否消失
3. 确认数据库中配置行是否存在
4. 查代码的 key 映射/id 类型

适用于所有使用 `atomic.Value` 缓存配置的模块，不限于 gdconf。
