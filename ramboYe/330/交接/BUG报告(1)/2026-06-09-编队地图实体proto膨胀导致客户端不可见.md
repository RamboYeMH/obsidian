# BUG：编队在跨服地图卡在静态阻挡导致 proto 膨胀，客户端地图不可见

## 现象

- 玩家 3342859（game223）4 号编队显示"返回中"，但地图上看不到该编队
- 客户端日志确认：`EntitiesNtf` / `WildMapViewNtf` 同步了地图对象，随后 `DelEntitiesNtf` 把它删掉
- 客户端有时能看到该玩家的另外 2 个编队，有时一个都看不到
- 每次重新登录远征地图，行为存在随机性

---

## 根因

### 触发链路

1. **00:36:19** cross1002 上该编队（entity `7649064363113799119`，lineupid `7579619698346440026`）在战斗后 `redif`，进入返回行军
2. **00:39:38** 行军路径经过坐标 `{4401500, 4399500}`，该点被静态建筑物 entity `7648722969257706597` 占据
3. 每次 march tick（~0.5s）触发 `CheckCollision`，代码路径：

```
CheckCollision
  └─ doPush(entity, collider, blockR)        ← ①先执行：secs = make([]MoveSection, len+2) + StartMove
  └─ CanPlaceNavAndObstacleWithRadius → false ← ②再检查：静态阻挡，return
```

`doPush`（`moving.go:152`）每次调用：
```go
secs := make([]MoveSection, len(move.Sections)+2)  // +2 永久追加
entity.StartMove(move.TargetID, move.TargetCoord, secs)
```

4. 卡死 16+ 小时，约 2次/秒 × 57600s ≈ **23 万条 sections**，entity proto ≈ **4.18MB**（从 4,101,257 → 4,179,613 bytes，增长速率 ~4KB/min 完全符合计算）

### 4MB 实体如何阻断客户端同步

**`OnPlayerMapUnitsReq` 路径（编队列表刷新）：**
- 无 diff 机制，每次全量打包玩家所有实体（6 个：5 支编队 + 城池）
- 4MB 实体使整包超出 gateway 消息大小限制 → 包被丢弃 → 客户端编队列表刷新失败

**`WildMapViewAck` 路径（地图视野）：**

```
PackWildMapViewAck:
  needAllView = (observer.LogoutTime > 0)  // 下线后首次 = true
  addViewPlayerUnit → 把玩家全部编队加入 units（含 4MB）
  DiffRectUnits(units, reconnect, pid)
  ResetLastView(units, noDelUnits)         // ← 先于发包更新 LastViewUnits（不管包有没到达）
  if needAllView { newUnits = units }      // 覆盖 diff，强制全量
  → 发包（含 4MB）→ 超限丢包
```

**为什么"有时能看到 2 个，有时一个都看不到"：**

| 情况 | 原因 | 结果 |
|------|------|------|
| 登录后第 1 次 WildMapViewReq | `needAllView=true` 强制全量，含 4MB 实体 → 丢包 | 看到 0 个 |
| 同一会话内第 2 次 WildMapViewReq | `ResetLastView` 已把 4MB 实体写入 `LastViewUnits`；`DiffRectUnits` 视其为"重复"，不重复打包 → 小包，只含视野内 2 个正常编队 | 看到 2 个 |

随机性来源：取决于玩家在**第 2 次视野刷新触发前是否已退出**。每次登录后第 1 次请求必然丢包，第 2 次必然成功，行为完全确定，不是真正的随机。

## 修改方案

### 修改一（根本修复）— `moving.go` `CheckCollision`

将静态阻挡检查移到 `doPush` **之前**，并加 `move.Fly()` 使编队飞越障碍（与 `doDetour` 失败的处理方式一致）：

```go
// 先判断静态阻挡 —— 必须在 doPush 之前，否则 doPush 每次 +2 sections
radius := entity.GetRadius(cspb.RadiusTypeBlock) + colliderEntity.GetRadius(cspb.RadiusTypeBlock)
if !em.CanPlaceNavAndObstacleWithRadius(colliderEntity.GetCoord(), radius) {
    tlog.Infof("%d %d static block cant doDetour at coord:%v", entity.GetID(), colliderEntity.GetID(), colliderEntity.GetCoord())
    isChange = true
    move.Fly()   // 飞越障碍，同 doDetour 失败的处理
    return isChange, isStop, isPause
}

// 非静态阻挡才执行挤出
dst := geo.CalDstCoordToCoord(colliderEntity.GetCoord(), curCoord)
blockR += types.MarchingClosestDistance
if util.Ac.SmallerOrEqual(dst, float64(blockR)) {
    tlog.Infof("%d %d push entity at coord:%v", entity.GetID(), colliderEntity.GetID(), colliderEntity.GetCoord())
    em.doPush(entity, colliderEntity, blockR)
}
```

**为什么加 `move.Fly()`：** 不加则 `isChange=false`，编队既不前进也不停止，无限卡死在静态阻挡处，只是不再膨胀。`move.Fly()` 让编队进入飞行模式（绕过碰撞检测 N 秒），穿越障碍继续行军。

### 修改二（兜底防护）— `doPush` 加 sections 上限

```go
const maxSections = 200
if len(move.Sections) > maxSections {
    tlog.Warnf("entity %d sections count %d overflow, skip append in doPush", entity.GetID(), len(move.Sections))
    em.UpdateEntityCoordFunc(entity, newCoord)
    entity.SetCoord(newCoord)
    return
}
```

### 修改三（防御纵深，可选）— `OnPlayerMapUnitsReq` 跳过超大单体实体

```go
const maxSingleEntityBytes = 512 * 1024  // 512KB 单实体上限
entityBytes := entityInfo.Size()
if entityBytes > maxSingleEntityBytes {
    tlog.Errorf("OnPlayerMapUnitsReq skip entity %d size=%d exceeds limit", u.GetID(), entityBytes)
    continue
}
```

即使将来类似问题再出现，客户端也不会因单个坏实体导致整包被丢。
