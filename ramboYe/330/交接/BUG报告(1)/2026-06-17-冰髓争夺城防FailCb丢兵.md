# BUG：冰髓争夺强制结算并发城防 FailCb 版本过期导致丢兵

## 问题描述

玩家 3862086（炎黄懒大王）区服 293 反馈：昨晚参加冰髓争夺后丢失约 40 万兵，从 170 万降到 129 万。

## 触发条件（同时满足）

1. 玩家正在跨服冰髓争夺图（cross1011 MAP_EXPEDITION）参与大型防守战（joinpassive）
2. 防守战战斗激烈，`toDefenderInfo` 频繁更新，`TmpLineupVersion` 快速递增（966→967→968→969→970→971）
3. 22:00 冰髓强制结算与城防 FailCb 同时到达

## 根本原因

`setLineupDataFailCb`（`play/internal/ctl_lineup.go`）在版本号过期时直接 `return`，丢弃了 `HurtCount`：

```go
// 修复前
if req.VersionID != mgr.TmpLineupVersion {
    tlog.Infof("... ignore version %d %d", ...)
    return  // ← BUG：HurtCount 被丢弃
}
```

**为什么 HurtCount 不会在新版本里还原：**

- `toDefenderInfo` 每次调用会 `lineupMgr.HurtSoldiersCount = 0`（reset）
- 版本 967 发送 `P2MChangeTroop(HurtCount=A)` 后立即 reset
- 版本 971 的 `setLineupDataOkCb` 只处理 `DeadCount`，不处理 `HurtCount`
- 因此 versions 967-970 各自的 `HurtCount` 是独立的，不在任何后续 callback 里

**关键日志证据（22:00:01 前后）：**

```
setLineupDataFailCb ignore version 967 971   ← HurtCount 丢弃
setLineupDataFailCb ignore version 968 971
setLineupDataFailCb ignore version 969 971
setLineupDataFailCb ignore version 970 971
setLineupDataOkCb addEasterSoldier deadSoldier:93   ← 只处理 dead
```

4 个 FailCb 共丢弃约 40 万伤兵（每轮约 10 万 × 4 版本）。

## 修复方案

`play/internal/ctl_lineup.go` `setLineupDataFailCb` 函数：

```go
// 修复后
if req.VersionID != mgr.TmpLineupVersion {
    tlog.Infof("... ignore version %d %d hurtCount:%d", ..., req.HurtCount)
    // 每次 toDefenderInfo 重置 HurtSoldiersCount，该版本伤兵不会被新版本覆盖
    if req.HurtCount > 0 {
        play.AddSlgCampRedif(p, req.HurtCount, def.ReasonIDRedifBackHurt)
        // ... BILog
    }
    return
}
```

- `SoldiersInfo`（存活兵）**不还原**：新版本成功上图，战斗结束会正常回城
- `HurtCount` **必须还原**：此轮独有，不补回就永久丢失
