# 零点跨天内存拉高根因：联盟战医院统一到期批量加载

日期：2026-08-18
影响：game844-859 零点跨天内存拉高
关联：game855 深度分析（goal dispatcher 累积为长期问题，与本次拉高无关）

## 结论

零点拉高 = **联盟战（LeagueWar）战地医院统一到期关闭**，对每个有医院数据的玩家
触发 `GetPlayerAsyn` 批量加载进内存做结算（发复活邮件），加载量 = 医院玩家数。

## 证据

1. **每服零点 10 分钟约 1.3-1.4 万次关闭触发**（source=ctl_league_war_hospital.go:379）
   - game844: 14270 / game854: 12833 / game859: 12972（按分钟聚合，避免 ES size 截断）
   - 00:00 起 1000+/分钟，峰值 00:01 ~1900+/分钟，00:09 后衰减，00:10 归零
2. **零点前静默**：23:50-23:59 为 0 条
3. **昨天/前天同窗口为 0 条** → 今日特有事件，非每日例行
4. 12h 内医院日志仅 Close + Settlement，无 AddDeaths/Revive → 统一到期关闭
5. 定时器注册：`LeagueWarHospitalInit` 按 `GetHospitalEndTs()-now` 注册
   （ctl_league_war_hospital.go:499-513），同一结束时间 → 零点同时到期
6. 今天联盟战进行中（战力排名持续上报活动服）

## 机制

```
联盟战医院结束时间 GetHospitalEndTs（玩家统一）
  → 定时器 TimerTypeLeagueWarHospitalClose 同时到期（每个玩家一个）
  → OnTimerTypeLeagueWarHospitalClose
    → GetPlayerAsyn(playerID)  ← 批量异步加载玩家进内存
      → LeagueWarHospitalSet   ← 结算 + 发复活邮件
```

## 与现象吻合

- "特定时间的功能" = GetHospitalEndTs 零点统一到期
- "人数相关" = 触发量 = 有医院数据的玩家数（1.3-1.4万/服），玩家多的服拉高更明显
- "新服更明显" = 新服联盟战参与人数/医院数据规模不同

## 优化方向（待确认）

- `OnTimerTypeLeagueWarHospitalClose` 批量 GetPlayerAsyn 是 CPU/内存尖峰源
  - 考虑：分批加载（rate-limit GetPlayerAsyn）、复用已在线玩家、延迟结算错峰
  - 确认 GetPlayerAsyn 是否对离线玩家也强制加载（否则可跳过纯结算场景）
