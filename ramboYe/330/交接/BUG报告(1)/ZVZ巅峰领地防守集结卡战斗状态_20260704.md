## 根因

两个代码缺陷叠加：

### 缺陷 1: `giveUpTarget` 不调用 `battleEnd`（已知 Bug）

`ctl_battle.go:694-699` 代码注释记录：

> 王座战出了个bug 三个个人编队去攻击哨塔让城防部队变成了集结。先到的编队设置target和whoattackme成功，后面两只编队设置whoattackme失败。先召回最先到的编队，然后再召回后面两只编队，这样在追击失败调用thronedefendend时不会解散集结。后面两只编队并不会被追击而只会调用giveuptarget，这里面只会结算发战报，并不会调用thronedefendend，导致编队卡住。

**关键路径**：`giveUpTarget` 中 `!targetBatUnit.BatCtx().InBattle()` 检查（line 701-702），在多攻击方场景下，后召回的编队走 `giveUpTarget` 路径只发战报，不触发 `battleEnd` → 不调用 `CCityDefendEnd` → 战斗状态不清理。

### 缺陷 2: `recallPlayerTroop` 条件过严

`ctl_map.go:1890-1892`：

```go
if rally.IsBattling() && rally.BatCtx().GetCurTarget() == nil {
    wmap.recallPlayerTroop(t)
}
```

在持续有攻击方到来的场景下，`GetCurTarget()` 永远不为 nil → 召回被完全绕过 → 防守方部队在集结中无法退出。

## 复现条件

1. ZVZ/巅峰领地 CentralCity（传送塔）形成防守集结
2. 多支攻击部队持续到达（不少于 2 波）
3. 防守方玩家尝试召回部队
4. 召回被 `GetCurTarget() != nil` 拦截，部队卡住

详见：[联盟战龙巢集结卡战斗状态-测试用例](zvz集结卡战斗状态-测试用例_20260704.md)

## 修复方案

> **已实施**：`/home/wenyu/Documents/h5/dev/330gs/`，待测试验证后合并到线上仓库。

### 修复 1：`battlectx.go` — 清除目标残留 CurTarget

**文件**: `game/wmap/internal/battle/battlectx.go:991`

**根因链路**：
```
GiveupTarget() → 只清攻击方自己的 CurTarget，不清目标的 CurTarget
→ InBattle() 对目标返回 true（GetCurTarget() != nil）
→ BattleEnd() 守卫门禁生效（if InBattle() → return）
→ giveUpTarget:701 的 battleEnd(target) 永远不会被调用
→ CCityDefendEnd 从不触发 → 集结状态不清理
```

**修改**：
```go
func (t *BatCtx) GiveupTarget() {
    curTarget := t.GetCurTarget()
    if curTarget == nil {
        return
    }
    curTarget.SetEndAttackInfo(curTarget.GetWhoAttack())
    curTarget.otherGiveupTarget(t)
    t.SetCurTargetBatCtx(nil)

    // 新增：当目标不再有任何攻击方时，清除目标的 CurTarget
    if len(curTarget.GetWhoAttack()) == 0 {
        curTarget.SetCurTargetBatCtx(nil)
    }
}
```

**影响范围验证**：`GiveupTarget` 的 8 个调用方中，`otherGiveupTarget` 已正确移除 WhoAttack 条目。新增的 `SetCurTargetBatCtx(nil)` 仅在 WhoAttack 真正为空时执行，不会误清正在交战中的目标。`battleChasingFail`、`BattleUnitDel` 等路径均不受影响。

### 修复 2：`ctl_map.go` — 放宽 recallPlayerTroop 召回条件

**文件**: `game/wmap/internal/ctl_map.go:1890`

**根因**：`checkRecallTroop`（`ctl_march.go:1057-1073`）在集结战斗中阻塞了正常客户端召回路径（返回 `ErrCodeRallyDefenseInBattle`）。唯一能绕过的 `OnP2MLineupCheckAndFix` 修复路径又被 `GetCurTarget() == nil` 限制。

**修改**：
```go
// 原来:
if rally.IsBattling() && rally.BatCtx().GetCurTarget() == nil {
    wmap.recallPlayerTroop(t)
}

// 修复后:
if rally.IsBattling() {
    wmap.recallPlayerTroop(t)
}
```

**安全性验证**：`recallPlayerTroop` → `GiveUpTroopAction` → `giveUpTarget`，配合修复 1 会正确清理目标 CurTarget。已有路径（`DisbandRallyTroop`、`ForceDisbandRallyTroop`、`ctl_zvz`、`ctl_battlefield`）已证明战斗中直接调 `recallPlayerTroop` 安全。

### 修复链路

```
修复前:
  GiveupTarget() → 目标.CurTarget 残留 → InBattle()=true → BattleEnd()=no-op
  → battleEnd 永不触发 → 战斗状态卡住
  → 玩家无法退出（checkRecallTroop 拦截 + recallPlayerTroop 条件过严）

修复后:
  修复1: GiveupTarget() → WhoAttack 空 → 清目标.CurTarget → InBattle()=false
        → BattleEnd() 正常执行 → CCityDefendEnd → 状态清理 ✓
  修复2: recallPlayerTroop 无条件召回 → GiveUpTroopAction → giveUpTarget
        → 结合修复1 → 目标状态正确清理 ✓
```
