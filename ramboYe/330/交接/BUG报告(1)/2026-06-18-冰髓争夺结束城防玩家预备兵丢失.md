## 问题描述

冰髓争夺战斗阶段结束时，若玩家城堡正在被 NPC 魔物攻击（城防战斗进行中），`RecallAllTroopsOnEndPhase` 执行后该玩家的预备兵变为 0。

- **发现版本**：1044
- **线上案例**：玩家 3862086，cross1011，2026-06-16 22:00 附近
- **内网复现**：玩家 467094，h5-dev3_cross777 + h5-dev3_game1222222，2029-11-13 22:00:00

---

## 根本原因

### 两个系统的时序冲突

`RecallAllTroopsOnEndPhase`（wmap 同步操作）和城防 `P2MChangeTroop` 握手协议（play↔wmap 异步消息）之间存在时序冲突：

1. **wmap 侧**：`RecallAllTroopsOnEndPhase` 先调用 `PTroopRtCity` 发出 16 条 `M2PTroopSetLineupData`，然后立即 `DelUnit(rt)` 删掉 RallyTroop（同步，<1ms 完成）。

2. **play 侧**（几毫秒后）：收到 8 条普通编队回城消息，因 `BeAttack=true && in>0`，每条都触发 `toDefenderInfo`：
   - 第 1 次：读 `HurtSoldiersCount=221258` → `toDefenderInfo` 将其清零 → 版本 1575→1576 → 发出 `P2MChangeTroop{HurtCount=221258, v1576}`
   - 第 2-8 次：`HurtSoldiersCount=0` → 发出 `P2MChangeTroop{HurtCount=0, v1577..1583}`

3. **wmap 侧（OnP2MChangeTroop）**：`P2MChangeTroop` 到达时 `defTroop = getPlayerCityDefender(city)` 返回 **nil**（DelUnit 已执行），全部以 `sendPlayM2PChangeTroopFail(flag=2)` 失败回传，`M2PChangeTroopFail{HurtCount=221258, v1576}` 被原样返给 play。

4. **play 侧（setLineupDataFailCb）**：版本 v1576 ≠ 当前 1583 → 进入 stale 分支 → `AddSlgCampRedif(221258)` **被注释** → 221258 伤兵永久丢失。

### IceContest 场景独有的放大因素

普通城防自然结束（PCityDefendEnd）时，`toDefenderInfo` 只调用一次（无普通编队同时回城），版本不会连续跳跃，无 stale 问题。IceContest 场景中 8 支普通编队同时回城，各触发一次 `toDefenderInfo`，版本从 v1575 连跳至 v1583，使 v1576 的 HurtCount 成为"孤儿"，只有 stale 分支的 `AddSlgCampRedif` 能补回。

```
│

    v1577..1582 → stale → hurtCount=0 → 无影响
```

### 伤兵数据来源

- `HurtSoldiersCount=221258` 来自 wmap 侧 `M2PTroopSyncDamage`（syncRoundOver 每秒推送，versionID=1575，21:59:33-21:59:59 持续累积）
- `selfTroop.HurtCount=0`：wmap 侧 `selfTroop.HurtCount` 只在 `OnP2MChangeTroop` **成功**时更新，城防战斗中从不成功 → 始终为 0
- `city.HurtCount=221258`：wmap 侧独立维护，有 TODO 注释"返回给伤兵给 play"，**未实现**

## 修复方案

### 主修复（已应用）

**文件**：`game/play/internal/ctl_lineup.go`，`setLineupDataFailCb`

**提交**：`4b04862d`（编队丢失预备兵）

stale 分支恢复 `AddSlgCampRedif`：

```go
if req.VersionID != mgr.TmpLineupVersion {
    tlog.Infof("... ignore version %d %d hurtCount:%d", ...)
    if !play.GetGmDisableRedifBackHurt() {
        if req.HurtCount > 0 {
            play.AddSlgCampRedif(p, req.HurtCount, def.ReasonIDRedifBackHurt)
            // + BILog
        }
    }
    return
}
```

**GM 开关** `GetGmDisableRedifBackHurt()` 提供线上紧急关闭能力。

### 安全性验证（多次补兵分析）

不会重复补兵，原因：
1. `HurtSoldiersCount` 每次 `toDefenderInfo` 清零 → 只有 v1576 携带 221258，后续版本携带 0
2. stale 分支 `return` 后绝不进入 `calcSoldier`（互斥）
3. M2PTroopSyncDamage 不同时间窗口累积，各版本 HurtCount 代表不同区间，不重叠

### 残留问题（未修复）

`game/wmap/internal/ctl_city.go:360`：

```go
tlog.Infof("%d redif citybattle end hurtcount:%d", city.Owner.ID, city.HurtCount)
```

城防战斗自然结束（PCityDefendEnd）后，`city.HurtCount` 仍未返还给 play，日志显示 IceContest 结束后持续的城防战斗（22:00:58, 22:02:00 等）分别产生 133052、140671 的额外丢兵，需后续实现。
