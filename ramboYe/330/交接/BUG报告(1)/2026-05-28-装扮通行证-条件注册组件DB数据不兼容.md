# BUG：装扮通行证活动模块 init 失败（invalid comp type）

## 现象

服务启动时 actv 模块 init 报 emerg 错误，导致整个活动模块无法启动：

```
emerg   core/core.go:105  module *internal.ActvModule init error
[Actv][Module]load actv module err: invalid comp type,
prg={ActvID:7643488726890213691 CompType:1 OwnerID:0 Data:{...ranking...}}
```

## 涉及活动

| 字段 | 值 |
|---|---|
| ActvID | 7643488726890213691 |
| CfgID | 1012202 |
| Type | 37（ActvTypeCostumePass，装扮通行证） |
| Scope | 1（ActvScopeServer，全服活动） |
| OwnerID | 700 |
| StartTs | 1779638400000（2026-05-25 00:00:00） |
| State | 2（运行中） |

## 根本原因

### 版本差异引入的注册条件变化

**h5_new_tf_v1042_new（旧）**：
```go
// costume_pass/api.go
if a.Scope == gdactv.ActvScopeServer {
    a.RegComponent(CompTypeRank, a.Rank)   // CompType = 1
}
```

**h5_new_tf_v1043（新）**：
```go
if a.existRank() {   // = Scope==Server && cfg.RankList != 0
    a.RegComponent(CompTypeRank, a.Rank)
}

func (a *ActvTmplCostumePass) existRank() bool {
    if a.Scope != gdactv.ActvScopeServer {
        return false
    }
    cfg := gdconf.GetActivityDressUPPassSubjectCfg(a.GetContentID())
    if cfg == nil || cfg.RankList == 0 {
        return false
    }
    return true
}
```

1043 在原有 `Scope==Server` 的条件上，新增了对 `ActivityDressUPPassSubjectCfg.RankList != 0` 的检查。

### 时间线

```
2026-05-25  活动在 1042_new 代码下启动
              → Scope==Server 满足 → CompType=1 (Rank) 注册
              → 玩家开始积累排行榜数据并写入 DB

2026-05-25~28  DB 中积累了 15 名玩家的 ranking 进度（CompType=1, OwnerID=0）

某次部署  1043 代码上线

服务重启  → existRank() 执行：
              Scope==Server ✓
              GetActivityDressUPPassSubjectCfg(contentID).RankList == 0 ✗
              → existRank() 返回 false
              → CompType=1 不注册
              → LoadProgresses 读到 DB 里的 CompType=1 数据
              → GetComponent(1) == nil
              → "invalid comp type" → 模块 init 失败
```

### 设计缺陷

`comp_holder.go:63`：

```go
func (ch *GameActvComponentHolder) LoadProgresses(prgDatas []actv_com.ActvProgressData) error {
    for _, prgData := range prgDatas {
        comp := ch.GetComponent(prgData.CompType)
        if comp == nil {
            return fmt.Errorf("invalid comp type, prg=%+v", prgData)  // ← 直接 error
        }
        ...
    }
}
```

遇到 DB 中存在但代码未注册的 CompType，直接返回 error，导致整个 actv 模块 init 失败。

## 影响范围

- actv 模块无法启动，所有活动功能不可用
- 同样使用"条件注册"模式的活动也有相同风险：
  - `wish_pool/api.go`：`if existRank(cfg) { RegComponent(1, Rank) }`
  - `maze/api.go`：`if ... { RegComponent(2, a.Rank) }`
  - `costume_pass/api.go`（本次问题）

## 修复方案

### 短期（让服务恢复启动）

**方案 A**：将该活动 `ActivityDressUPPassSubjectCfg` 中对应 ContentID 的 `rank_list` 字段恢复为非零值

```js
// 查 content_id
db.ActivityOnlineCfg.findOne({id: 1012202})
// 修复 rank_list
db.ActivityDressUPPassSubjectCfg.updateOne({id: <content_id>}, {$set: {rank_list: 1}})
```

**方案 B**：清除该活动 CompType=1 的旧 ranking 数据（会丢失排行榜数据）

```js
db.actvprogress.deleteMany({actvid: Long('7643488726890213691'), comptype: 1})
```

### 长期（防止同类问题再次触发 module crash）

修改 `game/actv/internal/activity/template/base/comp_holder.go`，将未知 CompType 从 error 改为 warn+skip：

```go
// comp_holder.go:61
comp := ch.GetComponent(prgData.CompType)
if comp == nil {
    tlog.Warnf("skip unknown comp type (may be config changed), prg=%+v", prgData)
    continue   // 改为跳过，而不是 return error
}
```

## 验证

修复后重启服务，确认：
1. actv 模块 init 无 emerg 日志
2. 活动 `7643488726890213691` 正常加载
3. 排行榜数据可正常展示（若选方案A）
