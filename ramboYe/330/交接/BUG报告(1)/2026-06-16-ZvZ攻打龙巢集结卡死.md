# ZvZ 攻打龙巢集结卡死无法返回

## 现象

玩家反馈（cross1007，player 6706089）：
- 集结攻打城堡（ZvZ 龙巢 CentralCity）
- 集结发起人撤回
- 其他队伍**卡在城堡处无法返回**
- 集结仍显示在列表中

## 关键日志

```
[01:13:03] ERR rally_troop.go:413  the leader is nil
  (*RallyTroop).RemoveTroop
  (*WMap).DelPTroopInRTroop  ctl_rallytroop.go:567
  (*WMap).DisbandRallyTroop  ctl_rallytroop.go:469
  (*WMap).rTroopBattleEndAlive  ctl_rallytroop.go:273   ← 错误路径
  (*WMap).battleEnd
  (*WMap).battleTroopDead
  (*WMap).battlePrepare
  (*WMap).timerBattleTicker
```

00:06:50 还出现过从 `OnDisbandRallyReq` 触发的同类错误（领队手动解散时）。

## 根本原因

### Bug 1：攻击方 rally 从未设置 DefendCtx（核心）

**文件**：`game/wmap/internal/ctl_union_war.go:1967`  
**函数**：`pTroopArriveCCityAttack`

攻击方集结到达龙巢并发起攻击时，代码设置了 `SetUnionWarCtx`，但**缺少**：
```go
unit.SetDefendCtx(target.GetType(), target.GetID())
```

对比：防守方 `pTroopArriveCCityDefend`（:3794）正确设置了 `SetDefendCtx`。

**后果**：
1. `rTroopBattleEndAlive(attackingRally)` 中 `rt.GetDefendType() == MapUnitStub`
2. switch 所有 case 未命中（MapUnitCentralCity 路由失败）
3. 走到第 265 行兜底路径：`DisbandRallyTroop(rt, RallyDelTypeFinish)`
4. 若 `unionWarAutoOccupy` 已通过 `RTroopDefendCCity` 路径将部队放入驻防，`rt.Troops` 未被清空，二次 `DisbandRallyTroop` 会调用 `RecallTroop` **撤销刚才的占领**！

### Bug 2：checkExpeditionLeaderDisbandRally 拦截手动解散

**文件**：`game/wmap/internal/ctl_battlefield_blacklist.go:160`

```go
if rallyOwner == nil {
    return cspb.ErrCodeServerData  // 发起人无法手动解散 zombie 集结
}
```

当 `rt.Troops` 为空（zombie 状态），领队手动解散请求被阻断，集结长期显示在列表。

## 执行顺序（关键）

`battleTroopDead(garrison)` 内的执行顺序：
```
第455行: battleEnd(garrison)
  → rTroopBattleEndDead(garrison)
  → CCityDefendEnd(garrison, false)
  → unionWarAutoOccupy        ← 先处理攻击方占领
      → GetRallyTroopByID → 找到攻击 rally
      → processRallyAutoOccupy
          → RTroopDefendCCity（占领路径：rt.Troops 未清空！）
          → DisbandRallyTroop(cancel)（失败路径：rt.Troops 清空）

第470行: battleEnd(attackingRally)
  → rTroopBattleEndAlive(attackingRally)
  → DefendCtx=MapUnitStub → DisbandRallyTroop(rt, Finish) ← 错误路径
      若 rt.Troops 未清空 → 二次处理 → 撤销占领
      若 rt.Troops 已清空 → 空操作（无害）
```

## 修复方案

### Fix 2（保守、推荐先上）

`ctl_rallytroop.go`，`rTroopBattleEndAlive` switch 之后（第264行）添加：

```go
// ZvZ 攻击方 rally 由 unionWarAutoOccupy 处理，此处不重复解散
if rt.GetUnionWarCtx() != nil {
    return
}
```

### Fix 3（修复列表卡住玩家体验）

`ctl_battlefield_blacklist.go:160`，`checkExpeditionLeaderDisbandRally`：

```go
if rallyOwner == nil {
    if rt.OwnerInfo().ID == pid {
        return cspb.ErrCodeSuccess  // 发起人可强制清理 zombie 集结
    }
    return cspb.ErrCodeServerData
}
```

### Fix 1（治本，需验证双重调用副作用）

`ctl_union_war.go:1967`，`pTroopArriveCCityAttack` 添加：

```go
unit.SetUnionWarCtx(&munit.WarCtx{ID: target.GetID()})
unit.SetDefendCtx(target.GetType(), target.GetID())  // 添加此行
```

需要验证 `CCityDefendEnd(attackingRally, true)` 被调用时，`unionWarRallyDisband` 与占领已完成的状态是否冲突。

## 影响范围

- cross1007 从 00:06 到 01:35+ 共 2000+ 条 `the leader is nil` 错误
- 每次 ZvZ 攻城 rally 赢得战斗都触发
- 主要影响：占领可能被意外撤销 + zombie rally 卡在列表
- `IsDuplicatemgrMap()` 对 ZvZ 跨服地图返回 false，`RecallTroop` 会调用 `PTroopRtCity` 瞬间传送（不是真正永久卡住）
