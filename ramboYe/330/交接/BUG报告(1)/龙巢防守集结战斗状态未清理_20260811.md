# BUG - 龙巢防守集结战斗状态未清理，玩家部队永久卡在龙巢

## 现象

- **环境**: online / cross1007（远征跨服）
- **玩家**: 6487192(game501), 6444469(game501), 2972815(game218)
- **时间**: 2026-08-10 09:00 起，至排查时（22:00+）仍未恢复
- **表现**: 玩家部队驻防龙巢后，战斗结束但集结状态未清理，部队永久卡在龙巢中无法退出
- **特征**: 被其他玩家攻击一次后状态才解除（新攻击者加入→触发战斗→离开时触发 battleEnd→CCityDefendEnd 看到 InBattle:false→解散）

### 日志特征

- `ctl_union_war.go:2234` 反复打出 `龙巢防守战结束, InBattle:true`，集结永不解散
- 攻击者全部离开后（21:07:43 起），集结进入**静默驻留**状态：无 battleEnd、无 CCityDefendEnd、无 joinpassive
- `ctl_battle.go:182` 打出 `unit <防守集结ID> target 0 cannot found`，CurTarget 已失效

## 根因

### 核心缺陷

`BatCtx.otherGiveupTarget`（`game/wmap/internal/battle/battlectx.go:1009-1011`）在从被攻击者 WhoAttack 中移除攻击者时，**没有清理被攻击者的 CurTarget**：

```go
// battlectx.go:1009-1011 （缺陷代码）
func (t *BatCtx) otherGiveupTarget(other *BatCtx) {
    removeBattleTroop(&t.WhoAttack, other.GetTroopID())
    // 缺失：if t.GetCurTargetTroopID() == other.GetTroopID() { t.SetCurTargetBatCtx(nil) }
}
```

对比 `otherDead`（line 1045-1053）和 `otherDel`（line 1083-1085）都有 CurTarget 清理逻辑，`otherGiveupTarget` 漏掉了同一处理。

### InBattle() 判断逻辑

```go
// battlectx.go:898-909
func (t *BatCtx) InBattle() bool {
    if t.GetCurTarget() != nil {   // ← CurTarget 残留导致永远 true
        return true
    }
    if len(t.GetWhoAttack()) != 0 {
        if t.GetStartBattleTime() <= 0 {
            return false
        }
        return true
    }
    return false
}
```

CurTarget 残留 → `InBattle()` 永远返回 true → `RallyTroop.BattleEnd()` 直接 return 不清理 → `CCityDefendEnd` 中 `if !ctx.InBattle()` 永远不满足 → 集结不解散。

## 故障链路

```
1. 攻击者D调 GiveupTarget()
   （DisbandRallyTroop → GiveUpTroopAction → giveUpTroopBattle → giveUpTarget）

2. GiveupTarget() 内部调 curTarget.otherGiveupTarget(D)
   → 防守集结.WhoAttack 移除 D           ✓
   → 防守集结.CurTarget 仍指向 D 的 BatCtx  ✗  ← ROOT CAUSE

3. D.SetCurTargetBatCtx(nil)  // D 自己的 CurTarget 清了

4. giveUpTarget line 752: targetCtx.GetCurTarget() != nil
   （防守集结.CurTarget 残留 → 不为 nil）
   → 走 else 分支

5. line 759: targetCtx.GetCurTargetTroopID() == owner.GetID()（D.ID）
   → 满足条件，不 settle，不 early return

6. line 773: !targetBatUnit.BatCtx().InBattle()
   → 防守集结.CurTarget != nil → InBattle()=true → 条件不满足
   → battleEnd(防守集结) 不被调用

7. DelUnit(D) → BattleUnitDel(D) → TroopDel()
   → otherDel 也只清 WhoAttack（此时已空），不清 CurTarget
   → GetAttackMeList 返回空列表（WhoAttack 已空）
   → 不会对防守集结调 battleEnd

8. 最终：防守集结 CurTarget 残留 → InBattle()=true 永驻
   → exitBattleLogic 直接 return → DefenderForceCheck 无机会执行
   → CCityDefendEnd 永不被触发 → 集结永久驻留龙巢
```

## 复现步骤

1. **环境**: 远征跨服地图（crossN），龙巢 CentralCity 存在
2. **防守方**: 多支部队驻防龙巢，形成防守集结（DefendRally，`rt.IsDefender()=true`）
3. **进攻方**: 派多个集结（RallyTroop A/B/C/D...）攻击龙巢
4. **触发条件**: 防守集结在 `battlePrepare` 中反击其中一个攻击者（如 D），`CurTarget` 指向 D
5. **召回**: 进攻方所有攻击集结被同时召回（`RecallAttacks` 串行 `DisbandRallyTroop`）
6. **BUG 触发**:
   - D 的 `DisbandRallyTroop` → `GiveUpTroopAction` → `giveUpTarget` → `GiveupTarget`
   - `GiveupTarget` 调 `curTarget.otherGiveupTarget(D)`
   - 防守集结.WhoAttack 清除 D ✓
   - 防守集结.CurTarget **残留指向 D** ✗
7. **结果**: 所有攻击者离开后，防守集结 `InBattle()=true` 永驻
   - `exitBattleLogic` 直接 return，`DefenderForceCheck` 无机会执行
   - `CCityDefendEnd` 永不被触发
   - 集结卡在龙巢，玩家部队无法退出

### 复现要点

- 防守集结必须反击过攻击者 D（`CurTarget` 指向 D），否则 D 不在防守集结的 `WhoAttack` 中，不会触发 `otherGiveupTarget`
- 攻击者通过**召回/解散**路径离开（走 `GiveupTarget`），而非**死亡**路径（走 `otherDead`，有 CurTarget 清理）
- 多个攻击者同时被召回时，最后一个被删的攻击者触发该 bug

## 修复方案

### 方案 A（最小改动 - 修 otherGiveupTarget）

`battlectx.go:1009-1011` 补上 CurTarget 清理，与 `otherDead`（line 1050-1051）保持一致：

```go
func (t *BatCtx) otherGiveupTarget(other *BatCtx) {
    removeBattleTroop(&t.WhoAttack, other.GetTroopID())
    if t.GetCurTargetTroopID() == other.GetTroopID() {
        t.SetCurTargetBatCtx(nil)
    }
}
```

修复后：D 的 `GiveupTarget` 执行后，防守集结的 CurTarget 也被清空 → `InBattle()=false` → `giveUpTarget` line 773 条件满足 → `battleEnd(防守集结)` 被调用 → `CCityDefendEnd` 正常解散。

### 方案 B（兜底 - CCityDefendEnd 补 else 分支）

`ctl_union_war.go:2237-2241`，在 `if !ctx.InBattle()` 不满足时做兜底清理：

```go
if !ctx.InBattle() {
    shouldRecallOnLoss := !isWin
    wmap.unionWarRallyDisband(rallyTroop, centralCity, shouldRecallOnLoss, util.NowTs())
} else {
    // 兜底：InBattle 仍为 true 说明战斗状态残留，强制清理
    tlog.Warnf("龙巢防守战结束但 InBattle 仍为 true, 强制清理, CityID:%v", rallyTroop.GetDefendCtx().ID)
    ctx.SetCurTargetBatCtx(nil)
    ctx.SetWhoAttack(nil)
    shouldRecallOnLoss := !isWin
    wmap.unionWarRallyDisband(rallyTroop, centralCity, shouldRecallOnLoss, util.NowTs())
}
```

**建议两个方案都做**：A 修根因，B 防御性兜底。

## 复盘

- `otherGiveupTarget` 与 `otherDead`/`otherDel` 的处理逻辑不一致，遗漏了 CurTarget 清理
- 防守集结的解散完全依赖攻击侧事件触发 `battleEnd`，缺少独立的超时/状态巡检兜底机制
- `exitBattleLogic` 在 `!inBattle` 时提前 return，导致 `DefenderForceCheck` 这个专门为"驻防编队卡住"设计的容错机制无法执行
