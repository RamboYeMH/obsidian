# BUG：宠物精炼操作超时弹窗

## 现象

玩家 5743445（game415）反馈：进行宠物精炼操作后弹出"操作超时"弹窗，但道具正常扣除、属性也正常完成。

- 反馈时间：2026-06-07 18:00 CST（反馈滞后）
- 真实发生时间：2026-06-07 17:06–17:07 CST（日志定位）

## 日志证据

```

[09:07:18 UTC] syncPetPower playerId 5743445 petId 7648314109686710965 RefinedPower 21340  × 2

[09:07:44 UTC] syncPetPower playerId 5743445 petId 7648314109686710965 RefinedPower 28380  × 3  ← 最严重
```

`syncPetPower` 仅在 `OnPetRefinedReplaceReq`（确认替换）中调用。相同值同秒出现多次 = **客户端重试了确认替换请求**。

## 根本原因

**`OnPetRefinedReplaceReq` → `syncPetPower` → `ReCalcPower` → `refreshGodStepRank` 同步 Redis 写入耗时过长，超出客户端超时阈值。**

```
OnPetRefinedReplaceReq
  └─ syncPetPower (ctl_pet.go:1330)
       └─ ReCalcPower (ctl_power.go:118)
            └─ refreshGodStepRank (ctl_god_step.go:269)
                 ├─ for _, cfg := range gdconf.GetAllBecomeStrongerCfg()
                 │      play.RankPut(...)   // ← 循环同步 Redis 写
                 └─ play.PlayerRankPut(...)
```

`GetAllBecomeStrongerCfg()` 有多少条配置就发多少次同步 Redis 写，叠加往返网络延迟，处理时间超过客户端超时阈值。快速连续精炼时（33 秒内 8 次），延迟积累，超时弹窗出现频率升高。

## 数据安全性

| 问题 | 状态 |
|------|------|
| 重复扣道具 | **无** — 道具在 `OnPetRefinedReq` 阶段扣除，无重试迹象 |
| 属性错乱 | **无** — `ReplaceRefined` 幂等，重复执行同值覆盖 |

## 伴随的独立 Bug（不是本次超时原因）

```
calcCityPower pID:5743445 cfgId:101930011 conf is nil
```
每次 `syncPetPower` 必触发，是 tech 配置表缺少 `101930011` 条目，不影响宠物精炼逻辑但应修复。

## 修复建议

1. **主要**：`refreshGodStepRank` 中循环的 `RankPut` 改为批量写（`ZAddArgs` 合并）或异步延迟写（debounce 定时刷）
2. **次要**：对 `OnPetRefinedReplaceReq` 添加幂等去重，防止同一次精炼结果被重复 apply
3. **次要**：补充 tech 配置 `101930011` 或在 `calcTechPower` 中跳过缺失条目时不打 error 级别日志
