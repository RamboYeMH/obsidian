**日期**: 2026-07-10
**分支**: h5_new_tf_v1046
**严重度**: P1（影响行军体验，多玩家触发）
**状态**: 待修复

## 根因

**1046 提交 `e49469e0cd`（H5-7257 行军编队表现异常修复）引入了回归。**

### 变更对比

| 项目 | 旧逻辑 | 新逻辑 (1046) |
|------|--------|---------------|
| 回退函数 | `doPush` | `getCollisionBackoffCoord` |
| 回退距离 | `blockRadius + 100` ≈ 3100 | `selfRadius` = 1000 |
| doDetour 兜底 | 有（回退搜索历史路径段 + 起点兜底） | **删除** |

### 关键代码

`game/wmap/internal/mmap/melem/munit/mentity/moving.go`:

旧逻辑用 `doPush` 按阻挡体半径挤出：
```go
blockR += types.MarchingClosestDistance
if util.Ac.SmallerOrEqual(dst, float64(blockR)) {
    em.doPush(entity, colliderEntity, blockR) // 回退 blockRadius+100
}
```

1046 改成只回退自身半径：
```go
// 碰撞后只向行军反方向回退一个自身碰撞半径，避免按阻挡体半径被挤到很远
backoffVector := moveVector.Trunc(float64(selfRadius) / length)
backoffCoord := collisionCoord - backoffVector // 回退 selfRadius(1000)
```

同时 `doDetour` 删除了兜底 fallback——当所有路径段都在碰撞圈内时，旧逻辑会从路径起点重算，新逻辑直接返回 false。

### 死循环机制

```
行军 → 撞大建筑(R=3000) → 回退 selfRadius(1000)
  → 回退后距建筑仅3100（建筑边缘外100）
  → doDetour 尝试绕路 → 无兜底 → 失败或路径回到碰撞区
  → 再次行军 → 再次碰撞 → 循环
  → MaxMoveSectionCount 达到上限 或 PTroopRtCity 放弃
```

客户端表现就是“小地图上反复寻路转圈”。

## 影响范围

- **地图**: MAP_EXPEDITION (远征图, maptype=13)
- **实例**: cross1007
- **触发条件**: 部队行军路径上有大型建筑/营地（BlockRadius ≥ 2000）
- **影响**: 同一时段 cross1007 上 63 条 `static block cant doDetour`，大量 `backoff entity` 日志
- **恢复**: 部队最终触发 `PTroopRtCity`（回城）或 `MaxMoveSectionCount` 上限停止

## 修复建议

**方案 A（推荐）**: 恢复用 `blockRadius` 做回退距离

```go
// moving.go:191 — 当前
backoffVector := moveVector.Trunc(float64(selfRadius) / length)

// 修改为：回退距离加入 blockRadius
backoffDist := float64(selfRadius + block.GetRadius(cspb.RadiusTypeBlock))
backoffVector := moveVector.Trunc(backoffDist / length)
```

**方案 B**: 恢复 `doDetour` 的兜底逻辑（回退搜索 + 起点兜底），当 backoff 位置不合法时能从路径起点重算。
