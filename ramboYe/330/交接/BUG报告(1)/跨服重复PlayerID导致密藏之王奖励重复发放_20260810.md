# BUG — 跨服重复 PlayerID 导致密藏之王个人奖励重复发放

日期: 2026-08-10
环境: 线上 (h5prod)
玩家: 1562232 (game39 "无敌神无敌" / game33 "Player1562232")

## 现象

线上玩家 1562232 在今天凌晨收到两封密藏之王个人奖励邮件（远征个人排名奖励结算）。

triage / player 日志显示，2026-08-10 00:00 前后：

```
[game39] OnA2PPendPlayerMails mailinfo, PlayerID:1562232,MailType:1,MailCfgID:17116063
[game33] OnA2PPendPlayerMails mailinfo, PlayerID:1562232,MailType:1,MailCfgID:17116063
```

同一时间两个 game 实例（game39、game33）都向 PID 1562232 发送了相同配置的邮件。平台邮件服按 `id:1562232` 唯一投递，两封都进了同一个收件箱。

## 根因

### 直接原因（Why×3）

1. **Why 两个实例都有 PID 1562232?**
   FastLogin（`OnFastLoginReq`）在无缓存时**直接用客户端自报的 PlayerID 伪创角**（agenthook.go:644），不向 platform 申请新 ID。客户端指定了 game39 已存在的 1562232，game33 就创建了同 ID 玩家。

2. **Why FastLogin 能绕过 platform?**
   FastLogin 本意是测试/调试通道：有缓存 → 伪登录成功；无缓存 → 伪创角成功。两条分支都**不调 platform**（`PfCharacterLoginReq` / `PfCharacterCreateReq`），platform 完全不知情，characters 集合无记录。

3. **Why 活动邮件重复发放?**
   跨服活动（密藏之王）结算时，活动服广播 `A2PPendPlayerMails` 到跨服组内所有 game 实例，每个实例以 `playercache.GetOriginServerID() == conf.ServerID` 过滤。game39 与 game33 各有一个同 PID 玩家且 originServerID 都等于自身 ServerID，两个实例都通过过滤发邮件，平台按 `id:1562232` 唯一投递 → 两封。

### 排查过程（排除项）

- **bindrole 假设被排除**：查 platform `db.bindRole` 无 1562232 记录；`db.characters` 中 1562232 仅 server_id='39' 一条。GM 角色绑定流程（`cmdBindRole` → `BindRole`）会导致 characters 集合出现同 ID 多账号记录，与事实不符。
- **登录-转-创角路径也被排除为本次根因**：该路径（`OnCharacterLoginLoadPlayerCb` ErrNotFound → 创角）有 platform 角色记录为前提，且会打印 `1. loginstep OnCharacterLoginReq`，与日志不符。但它与 FastLogin 是同一类缺陷（创角无全局唯一校验），一并修复。

### 本质

PlayerID 全局唯一性校验缺失在**两条创角链路**上：

| 链路 | ID 来源 | 唯一性保证 | 状态 |
|------|---------|-----------|------|
| 正常创角（gsgate → platform character/create） | platform `GenPlayerID` $inc 自增 | ✅ 全局唯一 | 无问题 |
| 登录-转-创角（`OnCharacterLoginLoadPlayerCb`） | platform 已有 character_id | ❌ 无校验 | **已修复** |
| FastLogin 伪创角（`OnFastLoginReq`） | 客户端自报 | ❌ 无校验 | **已修复** |

## 修复方案（已落地）

在两条无校验的创角路径入口增加 platform 全局归属查询（`PfQueryPlayerServerIDReq`，已有接口，邀请码功能在用）：

### 修复 1：登录-转-创角路径 — `game/play/internal/ctl_login.go`

`OnCharacterLoginLoadPlayerCb`（:277）ErrNotFound 分支由直接创角改为 `checkPlayerExistBeforeCreate(req)`：

```go
func (play *Play) checkPlayerExistBeforeCreate(req *iproto.PlayCharacterLoginReq) {
	// 拒绝创建：查询失败或PID已归属其他服时统一回包
	reject := func(reason string) {
		tlog.Errorf("player%d checkPlayerExistBeforeCreate reject create, reason:%v", req.PlayerID, reason)
		play.SendToBySessionID(req.SessionID, &iproto.PlayCharacterLoginAck{Err: cspb.ErrCodeFramework})
	}
	// 1. 异步查询 platform：该PID当前归属哪个服
	play.AsynCall(conf.PFMOD, &pfproto.PfQueryPlayerServerIDReq{
		List: []string{strconv.FormatInt(req.PlayerID, 10)},
	}, func(ri *chanrpc.RetInfo) {
		// 2. 查询链路异常（网络/超时）：fail-safe 拒绝创建
		if ri.Err != nil { reject(fmt.Sprintf("query serverID err:%v", ri.Err)); return }
		// 3. 应答类型断言失败：fail-safe 拒绝创建
		ack, ok := ri.Ack.(*pfproto.PfQueryPlayerServerIDAck)
		if !ok { reject("ack type err"); return }
		// 4. 核心校验：PID已归属其他服 → 拒绝；归属当前服或不存在 → 放行
		if serverID, exists := ack.List[req.PlayerID]; exists && serverID != conf.ServerID {
			reject(fmt.Sprintf("already exists on server:%v, curServerID:%v", serverID, conf.ServerID))
			return
		}
		// 5. 校验通过：走原创角逻辑
		play.OnPlayCharacterCreateReq(&chanrpc.CallInfo{Req: &iproto.PlayCharacterCreateReq{...}})
	}, cbctx.M{})
}
```

### 修复 2：FastLogin 伪创角路径 — `game/gsgate/internal/agenthook.go`

`OnFastLoginReq` 无缓存分支由直接伪创角改为 `checkFastLoginPlayerExist(req)`：

```go
func (agent *GSAgent) checkFastLoginPlayerExist(req *cspb.FastLoginReq) {
	// 1. 异步查询 platform：该PID当前归属哪个服
	err := agent.AsynCall(conf.PFMOD, &pfproto.PfQueryPlayerServerIDReq{
		List: []string{strconv.FormatInt(req.PlayerID, 10)},
	}, func(ri *chanrpc.RetInfo) {
		// 2. 查询链路异常：fail-safe 拒绝创建并断开
		if ri.Err != nil { agent.sendToFrame(&cspb.LoginAck{ErrCode: cspb.ErrCodeFramework}); agent.Close(); return }
		// 3. 应答类型断言失败：fail-safe 拒绝创建并断开
		ack, ok := ri.Ack.(*pfproto.PfQueryPlayerServerIDAck)
		if !ok { agent.sendToFrame(&cspb.LoginAck{ErrCode: cspb.ErrCodeFramework}); agent.Close(); return }
		// 4. 核心校验：PID已归属其他服 → 拒绝；归属当前服或不存在 → 放行
		if serverID, exists := ack.List[req.PlayerID]; exists && serverID != conf.ServerID {
			tlog.Errorf("%v checkFastLoginPlayerExist pid:%v already exists on server:%v, reject fast login create", agent, req.PlayerID, serverID)
			agent.sendToFrame(&cspb.LoginAck{ErrCode: cspb.ErrCodeFramework}); agent.Close(); return
		}
		// 5. 校验通过：走原伪创角流程
		agent.fsm.SetState(AgentStatePfCreating)
		agent.OnPfCharacterCreateAck(&chanrpc.RetInfo{Ack: &pfproto.PfCharacterCreateAck{PlayerID: req.PlayerID}, Ctx: ...})
	}, cbctx.M{})
	if err != nil { agent.sendToFrame(&cspb.LoginAck{ErrCode: cspb.ErrCodeFramework}); agent.Close() }
}
```

### 方案取舍说明

- **未采用 platform `Login` 加 server_id 校验**：该方案会误伤飞服玩家——飞服（`ChangeServer`）只迁移 game 侧 DB，platform 侧角色 `server_id` 保持旧服值（`syncMeta` 仅在创角/登出时更新），飞服玩家目标服首次登录会被误拒
- **校验点选择在创角入口而非登录入口**：飞服玩家目标服登录时 DB 已有数据（已迁移），不会走 ErrNotFound 分支，天然免疫时序问题；只有真正要"新建"的路径才查全局归属

## 复盘

### 如何避免同类问题

1. **所有"DB 查不到 PID 就自动创角"的路径必须先做全局唯一校验**：登录-转-创角、FastLogin 伪创角均属此类。统一在 `OnPlayCharacterCreateReq` 入口校验可覆盖全部路径
2. **FastLogin 是测试/调试通道，却拥有完整创角能力且零校验**：应限制使用场景（平台白名单/仅内部 IP），或与正式创角同等的校验强度
3. **活动服广播发奖依赖本地过滤**：`OnA2PPendPlayerMails` 的 `OriginServerID == conf.ServerID` 过滤假设"跨服组内一个 PlayerID 只属于一个 game 实例"，该假设被跨服同 ID 破坏。可考虑活动服发奖时携带目标 ServerID 定向投递

### 遗留

- 已存在的重复 PID 玩家（game33 的 1562232）需要删除：platform 侧无记录无需处理；game33 侧仅 `player`/`playercache` 各 1 条、`playermail` 0 条（死号，注册当天上线一次后离线）。删除需确认无在线会话
- 当前没有"指定 server_id + playerId 删角色"的现成 GM 命令（`delme` 只能玩家自删，platform `DelCharacters` 需 account_id）
- platform `UpdateMetaInfo`（handler.go:350-390）存在 `if server_id != "0" { v.Server_id = server_id }` 逻辑，可被调用方篡改角色归属服，是否纳入校验范围需评估
