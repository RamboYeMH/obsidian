func genFakeStocks() []*model.BuildingStock {
    allCfg := gdconf.GetAllLandBuildingCfg()
    stocks := make([]*model.BuildingStock, 0, len(allCfg))

    return stocks
}

P2
两个商店文件 280 行逻辑完全重复，应合并为一个结构体
home_land_daily_shop.go · home_land_week_shop.go
reuse 设计建议

两个文件的所有方法（CheckCanBuy/Buy/CopySelf/ShowShopInfo 等）逐行对应，唯一区别是 Refresh() 中的刷新时间计算函数不同。每次改一处逻辑都必须同步改两处，这是典型的维护炸弹。

建议重构方案
type HomeLandShop struct {
    Record        map[int32]int32
    player        _interface.IPlayer `bson:"-"`
    play          _interface.IPlay   `bson:"-"`
    RefTime       int64
    Tp            cspb.ShopType
    nextRefreshFn func(int64) int64  `bson:"-"`
}

// Refresh 刷新（日/周由 nextRefreshFn 决定）
func (v *HomeLandShop) Refresh() {
    v.RefTime = v.nextRefreshFn(util.NowTs())
    v.Record = make(map[int32]int32)
}

值得肯定的地方

  • OnSaveHomelandLayoutReq 的阶段注释质量高：明确标注了"顺序固定，不可随意调整"及各步骤的前提约束（如"插件回调时 Layout 仍是旧状态，插件依赖这一前提"），属于高价值 WHY 型注释，帮助后续维护者避免错误调整顺序。
  • validateUpsertedBuildings 职责单一，提取得当：将复杂的校验逻辑从 OnSaveHomelandLayoutReq 中剥离，参数定义清晰，errCode 返回规范，易于独立测试。
  • handler.go 中 actvPreHandlers 注册表重构干净：将原来的大 switch-case 改为反射注册表 + 接口 actvCfgIdGetter，消除了每次新增活动消息都要修改 switch 的问题，扩展性明显提升。
  • model 层设计职责清晰：HomelandSystem / BuildingStock / Building 分层合理，PlaceAt / MoveTo / ToStock 语义明确，生命周期注释（ID 获取时分配、生命周期内不变）对理解数据模型很有帮助。
