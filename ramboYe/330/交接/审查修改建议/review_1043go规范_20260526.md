### P2-2 注释规范：ctl_crystal_tower.go 注释描述 WHAT

**文件：** `game/wmap/internal/ctl_crystal_tower.go:485`  
**规范：** 只在 WHY 非显而易见时加注释，不描述 WHAT

```go
// 水晶塔伤害由两部分组成：基于最大兵力的万分比 + 基于当前兵力的万分比
// 确保无论驻防部队是否满血，都能造成有意义的伤害
var totalDmg float64
```

这两行注释在描述代码做了什么（WHAT），而非解释为什么要这样设计（WHY）。读者通过函数名和变量名已能推断。若要保留，应改为说明设计意图，例如：

```go
// 两段叠加是为了在驻满部队立即被击溃的场景下仍能造成基础伤害
```

若 WHY 不需要记录，直接删除注释即可。

### P2-4 L5：GiveUp() 末尾 MakeDirty 部分冗余

**文件：** `game/wmap/internal/mmap/melem/mcity/ice_morrow_mine.go:240`  
**规则：** L5 — 同一调用路径上同一副作用不应重复执行

```go
func (mine *IceMorrowMine) GiveUp() {
    if mine.GetOwnerID() == mine.GetOccupyUnionID() {
        mine.SetOccupyUnionID(0)  // 内部 MakeDirty
        mine.SetOccupyEndTs(0)    // 无 MakeDirty
        mine.SetState(...)        // 内部 MakeDirty
        mine.SetDefendID(0)       // 内部 MakeDirty
        mine.SetDefendTroops(nil) // 无 MakeDirty
        mine.SetProtectTs(0)      // 内部 MakeDirty
    }
    mine.SetOwnerID(0)  // 无 MakeDirty
    mine.MakeDirty()    // 末尾显式调用
}
```

`SetOccupyEndTs`、`SetDefendTroops`、`SetOwnerID` 的 accessor 未带 `MakeDirty`，末尾显式调用是必须的。**但 `SetOccupyUnionID`、`SetState`、`SetDefendID`、`SetProtectTs` 内部已调用 `MakeDirty`，末尾再调用会执行多次 dirty 标记**（L5 重复副作用）。

这在功能上无害，但说明 accessor 的 `MakeDirty` 策略不统一，容易引发误解。

**建议：** 长期应让所有修改持久化字段的 setter 统一调用 `MakeDirty`，而不是在调用方手动补调，这样 `GiveUp()` 末尾的显式 `MakeDirty` 也可以删掉。可在 accessor_engine2 规则层面统一处理。
