# 1044 许愿池整理 代码审查

## 变更概述

4 个提交，主要工作：
- 删除 Redis 排行榜依赖（`actv_rank.go`），迁移为 `ap_rank` 组件
- 抽奖逻辑从 ~700 行巨函数拆分为 `doGrandPrize` / `doSpecialReward` / `doFixedReward` / `doOutputReward` 四步
- 阶段奖励逻辑独立为 `ActvPlayWishPoolStage`
- 个人库存从 `actvProgress.PersonStock`（`map[int32]map[int64]int32`）迁移到 `account.PersonStock`（`map[int32]int32`）
- 任务奖励从 `WishPoolQuestRewardReq` 改为 `ActvCommonQuestRewardReq`（ap_quest 组件统一处理）

## Bug 级别问题

### 1. [Critical] `pickSpecialReward` nil 解引用 → **必须修复**

**文件**：`lottery.go:320-322`

```go
cfg := ths.lotteryRewardByAccount(account)
tlog.Infof("... cfg:%+v Reward:%v", ..., cfg.Reward)  // cfg 可能为 nil，直接 panic
return cfg
```

**触发条件**：所有特殊奖励被过滤掉时（能量不足 + 库存耗尽），`lotteryRewardByAccount` 返回 `nil`。

**修复**：
```go
cfg := ths.lotteryRewardByAccount(account)
if cfg != nil {
    tlog.Infof("... cfg:%+v Reward:%v", ..., cfg.Reward)
}
return cfg
```

## 逻辑问题

### 4. `resetRecord` 用 ServerLogs 统计大奖次数不准确

**文件**：`comp.go:65-75`

`ServerLogs` 是展示日志（受 `TreviFountainNoticeMaxAll` 截断，跨轮次累积），不等于"本轮大奖次数"。会导致 `NoSuperRewardCircleCnt`（连续无大奖轮数）统计偏差，影响保底降级逻辑。

建议：在 `ActvWishPoolGroupPool` 新增 `CurCircleBigCnt int32` 字段，在 `RecordSuperRewardCnt` 时累加，`resetRecord` 时读取后清零。

---

### 5. 超级大奖 hit 槽被消耗但无降级奖励

**文件**：`lottery.go:251-255`

当超级大奖位置命中但玩家未满足 `NoBigDecrCnt` 阈值时，slot 被消耗、玩家一无所获（连降级小奖也没有）。若为有意设计，需在代码处加注释说明。
