# 审查流程故障分析 — homeland 家园系统

## 事件

用户请求"审查一下homeland家园系统相关的代码"，模型**跳过了路由表**，未调用 `full-code-review` Skill，手动读取文件输出审查结果。

## 根因

路由表正确命中了 `full-code-review`（优先级 11 > `go-review`），但模型执行层认为"Skill 太重了，直接手动做更快"，**把路由结果当建议而非规则**。

```
路由层： ✅ 正确 → full-code-review
执行层： ❌ 跳过 → 手动读文件、凭经验分类输出
```

## 跳过了什么

| 应该做 | 实际做 |
|--------|--------|
| 调用 `full-code-review` Skill | 手动 Read 文件 + 自己归类 |
| 按 `go-rules.md` 逐条对照检查 | 凭经验判断问题 |
| 归档审查结果到 SecondBrain | 只在聊天里输出 |
| 走标准化的审查 pipeline | 自由发挥 |
| 读取 homelandDoc/INDEX.md 作为 checklist | 读了文档但仅当背景知识 |

## 已实施的修复

### 1. routing.yaml — `routing_hints.non_skippable`
```yaml
non_skippable:
  - go-review
  - full-code-review
  - online-investigation
```
路由命中后必须调用 `Skill` 工具，禁止模型手动等效。

### 2. routing.yaml — `routing_hints.doc_discovery`
```yaml
doc_discovery:
  - skills: [go-review, full-code-review]
    pattern: "{topic}Doc/INDEX.md"
    action: "读取 INDEX.md → 遍历子文档 → 提取不变式/状态机/约定 → 作为审查检查项输入"
```
审查前自动发现并读取项目文档，文档当规格说明书用。

### 3. CLAUDE.md — Skill 强制调用规则
- 路由命中后必须 `Skill("X")` 调用
- 判断标准："觉得 Skill 太重想手动做" = 正是需要 Skill 的信号

### 4. CLAUDE.md — 审查+文档融合规则
- 文档当规格说明书，逐条验证代码是否匹配
- 文档 ≠ 代码时标记为问题
- 禁止"读了文档就过"

## 防范效果

下次遇到"审查 homeland 代码"：
1. 路由 → `full-code-review`（优先级 11）
2. 检查 `non_skippable` → 必须 `Skill("full-code-review")`
3. `doc_discovery` 触发 → 读 `homelandDoc/INDEX.md` → 提取状态机/约定
4. Skill 内部：go-rules.md 逐条检查 + 文档为 checklist + 归档
5. 模型无法"手动等效"跳过
