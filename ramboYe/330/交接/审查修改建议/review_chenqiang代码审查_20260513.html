容差配置取值逻辑重复
ctl_slgcamp.go:347-350  ·  ctl_tech.go:369-372
规范-5

同一段取容差配置的代码在 OnSlgCampProduceAccuReq 和 OnResearchCityTechAccuReq 中逐字重复。当前 2 处尚未触发规范-5 的三处阈值，但已经是潜在风险：若后续其他加速函数（建筑、指挥官等）也需要此逻辑，第三处出现时将构成正式违规，且届时散落在多个文件中更难统一修改。

ctl_slgcamp.go:347 & ctl_tech.go:369 — 重复出现两次
var toleranceSec int64
if toleranceCfg := gdconf.GetD2ConfigCfg(gdconf.ResearchAccuToleranceSec); toleranceCfg != nil {
    toleranceSec = int64(toleranceCfg.Val)
}
建议 — 提取为公共函数（可放 game/play/internal/ 或 slgcamp 包）
// getAccuToleranceSec 返回加速请求的时间容差秒数，读自 D2Config，无配置时返回 0。
func getAccuToleranceSec() int64 {
    if cfg := gdconf.GetD2ConfigCfg(gdconf.AccuToleranceSec); cfg != nil {
        return int64(cfg.Val)
    }
    return 0
}

// 调用处简化为一行
toleranceSec := getAccuToleranceSec()
目前不强制要求立即提取，但建议在下一次涉及加速函数的改动中一并处理，防止三处违规。
P2
配置常量命名语义不准确
gdconf/def_d2config.go · ResearchAccuToleranceSec
命名

常量名 ResearchAccuToleranceSec 对应配置 key "Research_Accu_Tolerance_Sec"，字面语义为"科技研究加速容差"，但实际同时被征召生产加速（OnSlgCampProduceAccuReq）引用，并非科技研究专属。后续维护者看到 Research 前缀，容易误以为该配置只影响科技功能，产生误判。

当前 — gdconf/def_d2config.go
ResearchAccuToleranceSec = "Research_Accu_Tolerance_Sec"  // 【科技】科技加速请求时间容忍秒数
建议 — 去掉 Research 前缀，注释说明适用范围
AccuToleranceSec = "Accu_Tolerance_Sec"  // 一键加速请求时间容差秒数（科技/征召通用）
gdconf 文件由 make conf 自动生成，改名需同步修改配置表的 key 名，改动前确认配置表是否已更新。若配置表暂时无法改，命名保持现状也可接受，至少把注释补全。
