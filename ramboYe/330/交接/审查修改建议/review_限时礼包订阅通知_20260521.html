订阅系统整体流程

整个推送体系分为注册阶段（玩家下线时写入 Redis）和发送阶段（Ticker 轮询消费），限时礼包通知接入注册阶段。

写入路径 — 玩家下线触发

绿色高亮节点为本次新增；PushQueue 与 TemplateMsgQueue 均为 Redis ZSet，Score = 发送时间戳

消费路径 — Ticker 定时发送

onTickerSubscribe 每 Tick 弹出到期消息，离线玩家写 SendWaitQueue（Redis Stream），在线玩家直接忽略

addTimeLimitGiftMsg 处理逻辑

红色节点表示提前 continue 跳过；绿色终点为成功写入队列路径

P1
抖音玩家无法收到限时礼包通知
ctl_subscribe.go:204 — onPlayerOfflineSubscribe
logic

onPlayerOfflineSubscribe 在最顶层对抖音玩家直接 return，导致 addTimeLimitGiftMsg 对抖音用户永远不会执行。 而 addTimeLimitGiftMsg 内部已通过 GetPlayerOpenId 获取正确的 MoHeDY channel，具备支持抖音推送的能力，但被上层过滤挡住。

当前结论：若业务明确不需要对抖音用户推送限时礼包，则此行为正确，需在代码注释中显式说明。 若未来需要支持抖音，改造点为此处。
ctl_subscribe.go:199–207 — 当前过滤逻辑
// 下线添加订阅消息

    if gconf.IsIceVersion() {
        return

    pPlayer := param.Get(gdevent.ParamPlayer).(*mplayer.Player)
    if pPlayer.IsDouYin() {   // ← 抖音用户全部跳过，含限时礼包通知

建议：在 IsDouYin() 判断处添加注释，明确说明"限时礼包通知暂不支持抖音渠道"，避免后续开发者误判为遗漏。

P1
多礼包同模板可能产生重复内容推送
subscribe.go:176 — addTimeLimitGiftMsg 遍历逻辑
logic

当玩家同时拥有多个礼包，且这些礼包的 SubNotifyTemplateId 配置为相同值（如均为 11001）时， 循环会对每个礼包分别调用 addPlayerMsg，在 Redis 中写入多条推送记录。 这些推送内容完全相同（同一模板文案），只有发送时间不同，玩家会在不同时刻收到多条措辞一致的通知。

若业务预期"每个礼包独立通知"则为正确行为；若预期"同类礼包只通知一次（最早到期那条）"则需要额外去重。 请与产品对齐预期后，在代码注释中说明策略。

P2
TimeLimitGiftExpire 常量未被逻辑代码引用
conf_subscribe_ext.go:93
style

新增的常量 TimeLimitGiftExpire = 11001 在运行逻辑中从未被引用—— 模板 ID 由 giftCfg.SubNotifyTemplateId 从配置表读取，不由常量硬编码决定。 常量当前仅作"推荐起始值"存在，容易让读者误以为代码强依赖此值。

当前 — 注释不足，语义模糊

✦ 正确改动 Praise

  • 三层 nil 防护完备：giftCfg、giftLimit、subItemCfg 均在使用前做了 nil 检查，不存在空指针风险（L2）。
  • playerId 缓存复用：循环外声明 playerId := player.GetPlayerId()， 避免在每次迭代中重复调用（符合规范 1、20）。
  • sendSecTs 作用域精准：使用 if sendSecTs := ...; sendSecTs > nowSecTs 的 if 初始化写法，变量生命周期严格限制在使用位置（符合规范 2）。
  • 超过3参数换行：play.addPlayerMsg(...) 5个参数全部换行对齐， 清晰易读（符合规范 7）。
  • 与已有模式高度一致：函数命名、调用链、Redis 写入方式均沿用 addShieldMsg、addDepotMsg 等已有函数的规范， 后续维护者可以凭已有知识理解此函数。
  • gdconf 改动最小化：仅在 D2GiftCfg 尾部追加一个字段， 不影响已有字段的存储映射；常量加在对应语义区块末尾，不破坏原有分组结构。

配置表联动说明

代码改动完成后，以下三张配置表需同步配置，否则功能不会生效。

需配置的表

D2GiftCfg
新增列 sub_notify_template_id（类型 int32）。 需要推送通知的礼包填入对应 SubscribeItemCfg 的 ID（如 11001）； 不需要推送的礼包填 0 或留空（默认为 0）。
SubscribeCfg
新增一行：Id = 11001，SubscribeItem = [11001]， Title / Content 填写订阅入口展示文案（玩家在订阅列表中看到的描述）。
SubscribeItemCfg
新增一行：Id = 11001。
  • Args[0]：提前通知分钟数（整数，如 30 = 礼包到期前30分钟推送）
  • Title：推送消息标题
  • Content：推送消息内容
  • Notice：推送尾部通知文案（含 %s 占位符，自动替换为玩家昵称）
验证方式：使用 GM 命令 SetGmOpenId 指定测试 openId， 下线后用 redis-cli 查看 WxSubscribe:PushQueue ZSet 是否在目标时间戳有新成员。
