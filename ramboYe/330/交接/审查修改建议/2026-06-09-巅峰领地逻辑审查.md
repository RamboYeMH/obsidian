# 巅峰领地（League War / ZVZ）逻辑审查报告

> 审查时间：2026-06-09
> 覆盖范围：zengbo 近期1044版本提交，涵盖 actv/league_war、union_power、holddata/peak_territory、game/play 侧

## P0 — 明确 Bug

### [Bug 1] JumpServerCD 判断逻辑完全反了

**文件：** `game/play/internal/ctl_league_war.go:144-148` / `193-196`

```go
// 进入战场（退出战场同样问题）
if p.JumpServerCD != 0 && p.JumpServerCD < util.NowTs() {
    return  // ← CD 已过期时才拒绝，CD 进行中反而放行
}
p.JumpServerCD = util.NowTs() + 5000
```

`JumpServerCD` 存的是**过期时间戳**。CD 进行中应满足 `JumpServerCD > NowTs()`，现在逻辑完全反了：CD 过期后才拒绝，CD 中反而放行。

**修复：** 改为 `p.JumpServerCD > util.NowTs()`

## P1 — 逻辑错误

### [Bug 2] Fcast 阶段 StageEndTs 语义错误

**文件：** `actv/.../league_war/api.go:499-500`

```go
case gdactv.ActvStateFcast:
    req.StageEndTs = fcastTs  // ← 预告「开始」时间，应为 startTs
```

`fcastTs` 是预告阶段自身的开始时间，不是结束时间。Fcast 阶段结束时刻是 `startTs`（活动开始）。Game 侧用此字段做倒计时，传错了。

**修复：** 改为 `req.StageEndTs = startTs`

### [Bug 3] 积分为 0 的参战联盟不触发降级

**文件：** `actv/.../league_war/api.go:collectUnionCategories`

```go
for _, item := range unionScoreRank.Dump(actvRgn.GetDeclareUnionCnt()) {
    // Dump 只返回曾调用过 UpdateDlt 的联盟
    // 全程零积分联盟不在其中，降级逻辑对它完全透明
    if item.Score == 0 && unionId != occupyUnionId {
        downgraded[unionId] = true
    }
}
```

一个联盟参战但全程未造成伤害/积分，`UnionScoreRank` 中没有它的记录，`Dump()` 不返回它。该联盟既不降级也不被归类为未晋级，静默保留在原圈层，与文档"积分为0的联盟降级"不符。

**修复：** 在 `settlePromotion` 补充遍历 `ActvUnions`，对不在 `UnionScoreRank` 中的参战联盟也执行降级判断。

## P2 — 设计实现不一致

### [Issue 4] RefreshRank 写入 holddata map 未 MakeDirty

**文件：** `actv/.../union_power/api.go:459-462`

```go
groups := peak_territory.GetUnionGroups()  // 返回 map 直接引用
for _, gs := range gdconf.GetAllServerListExt() {
    if gs.ZvzGroupId > 0 && groups[gs.ZvzGroupId] == nil {
        groups[gs.ZvzGroupId] = peak_territory.NewLeagueWarGroup()
        // ← 没有 LeagueWarMakeDirty()
    }
}
```

新写入的 LeagueWarGroup 不会被持久化协程落库，重启后丢失。

**修复：** 新增 group 后调用 `peak_territory.LeagueWarMakeDirty()`。

### [Issue 5] 无 UnionInfo 联盟跳过但战区仍创建

**文件：** `actv/.../league_war/api.go:120-134`

`applyMatchResult` 先标记 `usedLands[rgnId] = true`，再判断联盟 info 是否存在。若某联盟无 info，联盟被 skip，但战区 PendingRgn 仍然创建，产生"有地图无联盟"的孤立战区，锁定通知无法发出。

**修复：** 只在至少一个联盟成功写入 ActvUnions 的 rgnId 才加入 usedLands。

### [Issue 6] matchScore topN 配置被注释掉

**文件：** `game/play/internal/ctl_league_war.go:452-456`

```go
//topN := int(gdconf.GetD2ConstCfgInt64Value(gdconf.LeaguewarMatchScoreTopN))
topN := 20  // 硬编码
```

策划修改 `LeaguewarMatchScoreTopN` 配置不生效。

## P3 — 潜在风险

### [Issue 7] 最高圈层（layer=4）联盟晋级后无邮件反馈

**文件：** `actv/.../league_war/api.go:applyPromotion`

```go
if cur < gdconf.LeagueWarMaxRgnLv {  // layer == 4 时跳过
    promotedLayers[uid] = cur + 1
}
```

已在第4层的联盟即使占领王座也不进入 `promotedLayers`，`sendPromoteReward` 不给它们发邮件，玩家无保级成功反馈。

### [Issue 8] broadcastOccupyResult 中过期时间写入依赖调用顺序

**文件：** `actv/.../league_war/ctl.go:broadcastOccupyResult`

失败联盟 `ActvExpireTs = nowTs`、胜利联盟 `ActvExpireTs = endTs` 写入后，MakeDirty 在 `unionOccupyActvRegion` 末尾才调用，若两者之间重启，状态会回滚。风险较低但值得关注。
