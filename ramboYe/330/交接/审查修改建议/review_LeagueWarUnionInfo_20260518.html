Get() 读操作有写入副作用，污染 groups map
leaguewar_union_info.go · Get():84 / GetGroup():71
logic

问题说明：Get() 内部调用 GetGroup()，后者在 zvzGroupId 不存在时会 make 一个空 group 并写入 groups map。每次对不存在的 key 调用 Get，都会产生空 group 驻留内存——读操作改变了内部状态。

影响范围：GetUnionInfoGroups() 同样调用 GetGroup()。onUnionPowerRankCb 在每次排行榜刷新（每 30 秒）时对全量 zvzGroupId 调用，持续生成空 group，且空 group 会被错误地视为"该分区有联盟数据"。

潜在影响：BeSelectServerCnt 统计遍历 GetUnionInfoGroups() 结果，空 group 在当前逻辑下不影响计数，但写入副作用是架构隐患，未来扩展时易出错。

DecodeFromDB 判空赋值与 accessor 懒初始化重复，是死代码
leaguewar.go · DecodeFromDB():125
spec

问题说明：原始 DecodeFromDB 中有 7 个 if nil { make(...) } 判空赋值块，用于初始化 DB 加载后可能为 nil 的 map 字段。但 accessor_engine2 生成的每个 Get 方法内部已包含相同的判空赋值逻辑——调用一次 Get 字段就会被自动初始化，因此外层判断条件恒为 false，7 个 if 块全是死代码。

根因：代码作者不了解 accessor_engine2 生成的 Get 方法内置了懒初始化，手动重复了相同逻辑。

以后新增字段时，在 ensureInit() 补一行 Get 调用即可，不需要手写 make。

写得好的地方

  • 按 group 拆分 MongoDB 文档：每个 zvzGroupId 独立一条文档（LeagueWarUnionInfo_<id>），避免单文档随参赛联盟数线性膨胀，读写粒度合理。
  • GetDirtyGroupDocs() 使用深拷贝：持久化前对脏数据做深拷贝再清脏标记，保证快照与后续写入互不干扰，防止数据竞争。
  • needDoMatch() 重启安全设计：用 endTs + matchDelayMs 时间条件替代一次性 Timer，服务重启后 OnTick 自动补偿执行，无需额外持久化 Timer 状态，设计简洁。
  • buildLayer1Supplement 去重逻辑清晰：用 seen map 统一处理"已在任意圈层"的去重，与入围逻辑复用同一套 fillLayer1FromRank，避免重复实现。
