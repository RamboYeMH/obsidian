### P0 · logic — L2 空指针：特殊奖励1 cfg 未检查 nil

**位置：** `actv/cactv/internal/activity/template/wish_pool_v2/lottery.go:315-318`

**问题说明：**  
`gdconf.GetTreviFountainprobabilityCfgByContentIdAndIndex()` 在配置 ID 不存在时返回 nil。特殊奖励2分支（新增代码）已正确加了 nil 检查，但特殊奖励1路径没有检查，两条路径不一致。当配置缺失时，直接访问 `cfg.Reward` 会导致 panic。

```diff
  if account.GetEnergy() >= wishPoolCfg.PPower[1] {
  	cfg := gdconf.GetTreviFountainprobabilityCfgByContentIdAndIndex(ths.GetContentID(), wishPoolCfg.PPower[0])
- 	tlog.Infof("... cfg:%+v Reward:%v", wishPoolCfg, cfg.Reward)  // cfg 未 nil 检查！
- 	return cfg
+ 	if cfg != nil {
+ 		tlog.Infof("... cfg:%+v Reward:%v", wishPoolCfg, cfg.Reward)
+ 	}
+ 	return cfg
  }
```

**修改建议：** 参照特殊奖励2的写法，在访问 `cfg.Reward` 前加 nil 检查。

> **根因：** 新加特殊奖励2时正确加了 nil 保护，但特殊奖励1是老代码未同步修改，导致两条路径保护不一致。

### P1 · logic — 逻辑不一致：getCampIceFrostTargets 未用 InNormal()

**位置：** `game/wmap/internal/ctl_ice_frost.go:473`

**问题说明：**  
本次新增了 `InNormal()` 方法并将 `isIceFrostTargetValid` 改用 `ec.InNormal()`，但同文件的 `getCampIceFrostTargets` 内部闭包仍用旧的三条件检查：

```go
// 旧写法（473行未改）
if !ok || ec.IsDestoryed() || ec.GetStatus() == gdconf.ExpBuildsStatusNone || ec.InCooldown() {
    return
}

// isIceFrostTargetValid 新写法（已改）
func (wmap *WMap) isIceFrostTargetValid(ec *mcity.ExpHordeCenter) bool {
    return ec.InNormal()
}
```

当前行为等价（`ExpBuildsStatusAttacked` 实际未被赋值），但：
1. 两处逻辑表达同一业务语义，代码维护时容易漏改其中一处
2. 若未来 `ExpBuildsStatusAttacked` 被使用，新旧逻辑语义会悄然分叉

```diff
  ec, ok := wmap.GetExpUnionCenterByID(id)
- if !ok || ec.IsDestoryed() || ec.GetStatus() == gdconf.ExpBuildsStatusNone || ec.InCooldown() {
+ if !ok || !ec.InNormal() {
  	return
  }
```

**修改建议：** 统一使用 `!ec.InNormal()`，保持与 `isIceFrostTargetValid` 一致，单一来源。

## 正确改动 Praise

1. **H5-9925 InNormal() 封装**：将 `!IsDestoryed() && status != None && !InCooldown()` 三条件封装为语义清晰的 `InNormal()` 方法，是非常好的语义化操作层实践（规范25）。调用侧代码从 3 个条件缩减为 1 个方法调用，大幅提升可读性。

2. **H5-9775 defer 修复**：将 `mapSendToPlayer` 改为 `defer` 放在函数头，确保无论中间 nil 检查提前 return，通知消息都会被发出。这是 Go 惯用模式的正确运用，同时保留了 `HasBattlefield()` 的早期退出（defer 在该 return 前未注册，不会发送）。

3. **H5-9919 BroadcastDelUnitsNtf**：先广播删除旧单位视图，再广播新状态，正确解决了视角内怪物行军时的客户端显示异常。`Del → Update` 的双广播模式处理得当。

4. **wish_pool_v2 ctl.go 消息类型修正**：将 `onWishPoolCloseBoxReq` 失败路径和成功路径中发送的消息类型从错误的 `WishPoolLotteryAck`/`WishPoolOpenBoxAck` 统一修正为 `WishPoolCloseBoxAck`，这是一个低调但重要的正确性修复。
