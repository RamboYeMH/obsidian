GM 强制匹配：continue 会使当前联盟没有任何分组
09a535101a H5-8936【联盟对决】GM强制匹配优化2

L6 逻辑遗漏 当强制对手已被匹配时，continue 跳过了整个后续流程——当前联盟既不写入 matchedUnions，也不生成任何分组（包括轮空 bye），相当于该联盟被静默丢弃，联盟对决数据中将不存在该联盟。

✗ 当前代码 — global/internal/ctl_union_duel.go
if len(forceUnions) > 0 {
    opponent = forceUnions[0]
    if matchedUnions[opponent.GetId()] {
        continue  // ← 当前 unionID 没有分组，被丢弃
    }
}
在正常成对强制匹配（A→B、B→A）下不触发此问题。但若强制名单配置异常（非对称、或对手不在参赛列表中）则必现。
✓ 建议修复
// 强制对手已匹配或不存在时，回退到正常匹配
if len(forceUnions) > 0 && !matchedUnions[forceUnions[0].GetId()] {
    opponent = forceUnions[0]
} else {
    opponent = m.findSuitableOpponent(matchKey, unions, i+1, serverID, matchedUnions, unionID)
}

processRoadWinner：死者弹出条件包含错误的 len(losers) > 1
ae3db12b48 H5-8787【联盟对决】突袭战斗判定逻辑有问题

L6 逻辑遗漏 修复后的条件将 len(losers) > 1 纳入判断，但胜者是否已死亡、是否应退出队列，与败方还剩几人无关。该条件是从第 270 行的"连胜换人"逻辑中照搬过来的，那里有"败方没人了也不换人"的明确设计意图，此处并不适用。

✗ 当前代码 — logic_battle.go:274
if !chgPlayer && winnerResult.IsDead() && len(winners) > 1 && len(losers) > 1 {
    winners = winners[1:]

两个新增函数缺少注释
aeb24082ec H5-8788 / H5-8790 当前联盟 ID 赋值

规范 OnCrossActvRankListReq 和 OnCrossActvUnionDuelMatchPlayerReq 均未添加注释。根据规范，每个函数必须有注释说明其功能。此处注释尤为重要——函数的核心行为是用服务端的 UnionID 覆盖客户端请求中的 UnionID，这是 bug fix 的关键逻辑，没有注释容易被误删或误改。

✗ 当前代码
func (play *Play) OnCrossActvRankListReq(player *mplayer.Player, message proto.Message) {
    req := message.(*cspb.CrossActvRankListReq)
    req.UnionId = player.GetUnionID()
    natsrpc.Cast(natsdef.Actv, gdconf.GetGroupID(), conf.ACTVMOD, req)
}
✓ 建议修复
// OnCrossActvRankListReq 转发排行榜请求，用服务端实时 UnionID 覆盖客户端字段，
// 防止客户端携带过期联盟 ID 导致展示数据错误（H5-8788/H5-8790）。
func (play *Play) OnCrossActvRankListReq(player *mplayer.Player, message proto.Message) {
    req := message.(*cspb.CrossActvRankListReq)
    req.UnionId = player.GetUnionID()
    natsrpc.Cast(natsdef.Actv, gdconf.GetGroupID(), conf.ACTVMOD, req)
}
