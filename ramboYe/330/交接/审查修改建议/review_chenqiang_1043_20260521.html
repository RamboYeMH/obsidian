P1
removeCrystalTowerDefender：if/else 两分支重复调用 RemoveDefender
game/wmap/internal/ctl_crystal_tower.go · 408
逻辑

无论 pt 是否为 nil，tower.RemoveDefender(unit.GetID()) 都需要执行，却写在了 if/else 两个分支里各一次。这不是 bug，但增加了维护成本——若将来修改 RemoveDefender 调用时机，极易漏改一处。

修改前 / 修改后 调用流程

修改前（冗余）
// removeCrystalTowerDefender
pt, _ := melem.UnitToPlayerTroop(unit)
if pt != nil {
    pid := pt.OwnerInfo().ID
    tower.RemoveDefender(unit.GetID())  // ← 分支1
    if !wmap.playerHasTroopsInBuild(tower, pid) {
        ...
        wmap.settlePlayerDefendBuild(tower, pid, expedition.CrystalTowerScore)
    }
} else {
    tower.RemoveDefender(unit.GetID())  // ← 分支2，重复
}
修改后（提前统一调用）
// removeCrystalTowerDefender
tower.RemoveDefender(unit.GetID())  // 无论 pt 是否 nil 均需执行，提前统一
pt, _ := melem.UnitToPlayerTroop(unit)
if pt == nil {
    return
}
pid := pt.OwnerInfo().ID
if !wmap.playerHasTroopsInBuild(tower, pid) {
    ...
    wmap.settlePlayerDefendBuild(tower, pid, expedition.CrystalTowerScore)
}
提前调用 RemoveDefender 不影响 playerHasTroopsInBuild 的语义——该函数检查的是"此玩家是否还有其他部队在塔中"，移除当前部队后再检查结果不变。

settleCrystalTowerDefendReward：defendMinutes 在内层循环重复计算
game/wmap/internal/ctl_crystal_tower.go · 325
逻辑

defendMinutes 仅依赖 recode.DefendSeconds，在外层 for pid, recode 迭代时固定，却写在内层 for _, cfg 循环中，每次 cfg 迭代都重新计算一次。此函数虽非热点路径（仅在争夺战结束时调用一次），但逻辑放置有误，应提到内层循环之外。

修改前
for pid, recode := range mgr.PlayerRecodes {
    var allReward []*reward.Reward
    for _, cfg := range allCfg {
        if cfg.Type != 2 { continue }
        defendMinutes := int32(recode.DefendSeconds / 60)  // 每次 cfg 循环重算
        if cfg.Value <= defendMinutes && ... {
        }
    }
}
修改后
for pid, recode := range mgr.PlayerRecodes {
    var allReward []*reward.Reward
    defendMinutes := int32(recode.DefendSeconds / 60)  // 提到内层循环外
    for _, cfg := range allCfg {
        if cfg.Type != 2 { continue }
        if cfg.Value <= defendMinutes && ... {
        }
    }
}
P2
settleCrystalTowerDefendReward 与 ExpAutoDemonFortressReward 奖励循环结构重复
ctl_crystal_tower.go:313  vs  ctl_island.go:2016
复用

两个函数的内层奖励循环逻辑完全一致：遍历 GetAllExpFortRewardCfg() → 按 cfg.Type 过滤 → 阈值比较 → ContainsInSlice 去重 → MakeReward 累积 → RewardsToAssets + 邮件 + BiLog。差异仅在 Type 值（1 vs 2）和阈值字段（Score vs DefendSeconds/60）。

两处重复的核心结构
// ctl_crystal_tower.go — Type==2，阈值=recode.DefendSeconds/60
for _, cfg := range allCfg {
    if cfg.Type != 2 { continue }
    if cfg.Value <= defendMinutes && !ContainsInSlice(recode.Reward, cfg.Id) {
        ...
    }
}

// ctl_island.go — Type==1，阈值=recode.Score
for _, Cfg := range allCfg {
    if Cfg.Type != 1 { continue }
    if Cfg.Value <= int32(recode.Score) && !ContainsInSlice(recode.Reward, Cfg.Id) {
        ...
    }
}
当前只有两处，可接受。若后续新增第三种驻防类型奖励，建议提取为共享 helper：
collectFortRewardByThreshold(allCfg, cfgType, threshold int32, rewardedIDs *[]int32) []*reward.Reward
