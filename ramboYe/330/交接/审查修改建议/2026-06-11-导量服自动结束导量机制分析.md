## 需求背景

开一个新导量服后，系统应自动把上一个导量服设置为**结束导量状态**（`ServerStatus_Done`），避免旧服持续接量。

该功能理论上由 commit `89e43c29`（2026-05-12，"自动开服:支持同时多个导量服"）实现。

---

## 核查结论

**代码逻辑本身正确，commit 已合并到当前分支（h5_new_tf_v1045），相关文件无后续覆盖。**

### 正常触发链路

```
运维平台开新服
  → AMQP 收到 GameWorldOpened 事件
  → IsPublic == false
  → loginTestWithTime(newServerId, 60s, cb)
    → 机器人登录成功
      → SetWeight(newId, 0, "newId", "")       // webserver/webs/devops/amqp.go:400
        → HTTP POST igame /manual/setweight
          → OnSetWeight(...)                    // igame/internal/receiver/handler/ctl_server.go:1131
            → importWorldSet = {newId}
            → 其余所有服 → ServerStatus_Done   // 结束导量 ✓
            → newId → ServerStatus_Fill         // 导量中 ✓
```

---

## 发现的风险点

### 风险1（高）：登录测试失败导致结束导量不触发

`SetWeight` 只在登录测试**成功**时才调用：

```go
// amqp.go:394
cb := func(code cspb.ErrCode) {
    if code != cspb.ErrCodeSuccess {
        Push("机器人登录新服失败...")   // 只发告警，不关闭旧服
        Phone(...)
    } else {
        SetWeight(...)  // 仅此处触发结束导量
    }
}
loginTestWithTime(int32(data.WorldId), WaitingforLogin*time.Second, cb)
```

**后果**：新服启动后 60 秒内机器人登录失败（服未完全启动、账号问题、网络），上一个导量服永久停留在 Fill 状态，继续接量。

**建议**：将"关闭旧导量服"与"新服登录测试"解耦。登录测试失败仅影响告警，不应阻止旧服关闭。或在失败回调中额外补一次 `SetWeight`。

---

### 风险2（中）：`lastImportWorldIds` 内存状态 webserver 重启丢失

```go
// amqp.go:27
var lastImportWorldIds string  // 进程内存，重启清零
```

重启后第一次收到同一 `importWorldId` 会重新执行 `OnSetWeight`，若运维期间手动调整过部分服的 Fill 状态，会被全量覆盖回 Done。

**建议**：将 `lastImportWorldIds` 持久化到 DB/Redis，或在 `OnSetWeight` 中增加幂等保护（只变更确实需要变更的服）。

---

### 风险3（低）：手动接口未传 `import_world_id` 时静默跳过

```go
// devops/amqp.go:319
if importWorldId == "" || lastImportWorldIds == importWorldId {
    return  // 无日志，静默退出
}
```

运维后台手动调 `POST /v2/server_import/setweight` 若不传 `import_world_id` 字段，整个结束导量逻辑不执行，且没有任何错误提示。

**建议**：加一行 warn 日志，或在接口层校验 `import_world_id` 不能为空。

## 排查建议（如发现线上问题）

1. 查钉钉推送历史，搜"机器人登录新服失败" → 确认是否 risk1 触发
2. 查 Kibana：`tlog.Infof("recvDelivery %d", res.Type)` 确认 AMQP 事件是否收到
3. 查 Redis/MongoDB：对应服的 `status` 字段当前值
