## 原文

# Obsidian 文档归档 skill（全局）

当任务产出是「文档」而非代码时，**写入 Obsidian 仓库**，不要只回复在对话里，也不要在当前项目代码目录里建 `.md`。此 skill 全局生效，不论当前在哪个项目/仓库窗口下工作，只要涉及整理文档、写学习笔记，都应触发。

## 仓库位置

VirtualBox 共享文件夹挂载点，**`ramboYe` 是 vault 根目录**：

```
/media/sf_obsidianRambo/ramboYe/
```

> 这是 Windows `C:\obsidianRambo\ramboYe` 下的个人知识管理库（VirtualBox 共享名 `obsidianRambo` → 宿主机 `C:\obsidianRambo`）。写入后用户在 Windows 的 Obsidian 里 `Ctrl+R` 重载即可见。

根目录下已有的顶级子目录包括：`指尖王国-游戏开发/`（游戏项目专属文档）、`Go语言学习/`（Go 语言体系化学习笔记）、`技术学习/`（其他技术专题，如 etcd、分布式系统）、`操作系统/`、`设计模式/`、`工具/`、`Claude/`。**不要把非游戏项目的内容误放进 `指尖王国-游戏开发/` 下**——那是专属于该游戏项目的工作文档目录。

## 目录归类规则

按文档类型放到对应子目录，**不要乱放根目录，不要把技术学习类内容嵌套进游戏项目目录**：

| 文档类型 | 目标目录 | 文件名约定 |
|----------|----------|------------|
| 游戏项目的模块/玩法设计、流程梳理、架构分析、调研 | `指尖王国-游戏开发/模块设计/` | `<主题>.md`，如 `登录流程.md` |
| 游戏项目需求单 | `指尖王国-游戏开发/需求/` | `<需求名>.md` |
| 游戏项目 Bug 单 | `指尖王国-游戏开发/Bug/` | `<单号> <简述>.md`，如 `H5-9953 远征挑战阵亡任务计数错误.md` |
| 游戏项目版本说明 | `指尖王国-游戏开发/版本/` | `v<版本号>.md`，如 `v1045.md` |
| 游戏项目工作日志 | `指尖王国-游戏开发/工作日志/` | `YYYY-MM-DD.md` |
| 游戏项目里 Golang 相关疑问/知识点速记 | `指尖王国-游戏开发/Golang项目疑问/` | `YYYY-MM-DD.md`（当天条目追加） |
| **非游戏项目**的源码学习/技术专题笔记（如 etcd、Raft、数据库原理、操作系统原理等） | `技术学习/<专题名>/` （vault 根目录下，与 `指尖王国-游戏开发/` 同级） | `<主题>.md`，如 `技术学习/etcd/Raft共识算法.md` |
| Go 语言体系化学习（跟随书籍/教程章节） | `Go语言学习/` （根目录） | `第<N>章-<主题>.md` |

新建前先 `ls` 对应目录，**已存在同主题文件就更新它，不要建重复**。总览看板在根目录 `总览.md`。

## 写作规范

1. **frontmatter 必填**（游戏项目文档）：参考 `模板/` 下对应模板（`_模板-需求.md` / `_模板-Bug.md` / `_模板-模块设计.md`）。统一字段：`类型`、`版本`、`状态`、`tags`、`创建日期`（用当前真实日期，绝对日期）。技术学习笔记可简化 frontmatter，但至少包含 `tags`、`创建日期`。
2. **基于代码事实**：梳理代码流程/设计时，必须实际读代码，引用 `文件:行号`（如 `gate/server/handler.go:382` 或 `raft/raft.go:1200`），不要泛泛而谈或臆测。
3. **流程图用 Mermaid**：Obsidian 原生渲染，时序图用 ` ```mermaid sequenceDiagram `。
4. **双链关联**：相关文档用 `[[文件名]]` 互链（如设计文档链到 `[[v1045]]`、学习笔记之间互链）。链接已有文档时用其准确文件名（不含 `.md` 也可）。
5. **中文为主**，术语/代码标识符保留英文。
6. 写完简要告诉用户**落到了哪个文件**，并提醒 Obsidian 里 `Ctrl+R` 重载。

## 不适用场景

- 纯代码改动、不产生文档时，不要硬写 Obsidian。
- 用户明确要求只在对话里回答时，遵从用户。
